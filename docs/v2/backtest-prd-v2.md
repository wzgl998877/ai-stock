## 执行摘要

面向 A 股个人投资者的**缠论信号历史回测**能力。系统使用与策略监控**完全相同**的缠论算法引擎，对用户全部自选股的历史 K 线重算缠论结构，统计每个已确认买/卖点信号出现后 N 日的真实涨跌表现，输出胜率、平均收益与分布图表，帮助用户回答一个关键问题：**这套缠论信号在历史上到底有没有用，哪类信号值得信任、哪类是噪音。**

**核心定位**：

- 回测是**评估工具**，不是交易模拟器——只统计信号后的客观涨跌，不模拟下单、不预测未来；
- 回测必须与实时监控使用**同一套算法、同一套确认规则**（收盘确认、不重绘），保证回测结论对实盘参考有效；
- 结果页面必须明示统计局限（样本量、生存者偏差、市场环境影响），防止用户把历史胜率当作未来保证。

---

## 问题陈述

**现状痛点**：

- 缠论信号是否正确无从验证，用户只能凭感觉信任或怀疑；
- 不同类别买卖点（一/二/三类）可信度差异大，但没有数据支撑判断；
- 用真金白银验证一个未经验证的信号体系，代价高昂。

**解决方案**：对自选股全部启用监控的股票，用与实盘一致的算法重算最近 3 年历史 K 线，统计每个信号后 5/10/20/60 个交易日的涨跌幅，给出胜率与收益分布。

**业务价值**：

- 上线实盘信号监控前，先拿到历史成绩单，建立或校准对系统的信任；
- 发现"胜率仅 40% 的信号类型"这类关键信息——它的价值在于**提前排雷**；
- 为未来参数调优、多周期共振评分提供数据基础。

## 回测口径（固定规则基线）

### 输入与范围

- **标的**：用户当前全部启用监控的自选股（按股票去重，与监控配置联动）
- **周期**：与监控一致，日线 + 30 分钟线（30 分钟信号统计以 30 分钟 K 线根数为窗口单位）
- **区间**：默认最近 3 年，用户可选 1 / 3 / 5 年
- **复权**：前复权，与监控一致
- **算法**：直接复用策略监控的缠论计算引擎与 `algo_version`，禁止单独实现

### 信号采集规则

- 只统计**收盘确认**的正式信号（confirmed 状态）；`invalidated` 信号不计入统计但在报告中标注剔除数量
- 每个信号记录：股票、周期、信号类型（buy1/buy2/buy3/sell1/sell2/sell3）、结构级别、信号时间、触发价
- 区间边界信号（确认后窗口超出数据末尾）：计入胜率统计，收益统计中标记为「窗口不完整」并单独计数

### 收益统计规则（信号后统计，不模拟交易）

- **观察窗口**：信号确认后第 5 / 10 / 20 / 60 个交易日（30 分钟周期按等根数换算：40 / 80 / 160 / 480 根）
- **收益计算**：`(窗口日收盘价 - 信号确认日收盘价) / 信号确认日收盘价`
- **买点胜率**：窗口收益 > 0 的信号占比；**卖点胜率**：窗口收益 < 0 的信号占比
- **统计维度**：按信号类型 × 周期 × 窗口交叉输出：样本数、胜率、平均收益、收益中位数、盈亏比（平均盈利幅度/平均亏损幅度）
- **分布图表**：各类型信号窗口收益的分布直方图
- **手续费**：本期不纳入统计（纯价格涨跌），报告中标注此简化

### 防偏差约束（必须遵守）

1. **无未来函数**：任何窗口内数据不得参与信号判定；信号判定与监控实时计算使用同一函数同一参数
2. **生存者偏差提示**：自选股天然只含现存股票，报告固定展示提示语：「回测标的均为当前在市自选股，未包含已退市股票，历史收益可能被高估」
3. **禁止调参**：回测只评估 PRD 固定参数的算法，不提供参数修改入口（参数自定义属 Phase 2 的策略优化需求，与本功能隔离）
4. **市场环境参照**：报告同时输出同区间沪深300（或基准指数）的累计涨跌，作为粗略市场参照

## 用户故事 & 验收标准

### Story 1：一键发起回测

**作为** 散户
**我希望** 点击一个按钮就对我的自选股跑完缠论信号回测
**从而** 不需要任何手动配置就能拿到结果

**验收标准：**

- [ ] 「策略监控」面板新增「信号回测」入口
- [ ] 发起时可选择区间：近 1 年 / 近 3 年（默认）/ 近 5 年
- [ ] 发起后 SSE 流式展示进度（已计算股票数/总数）
- [ ] 回测期间可离开页面，完成后下次打开直接展示最近一次结果
- [ ] 数据未同步完成时给出提示，建议先同步 K 线

### Story 2：看懂总体成绩单

**作为** 散户
**我希望** 一眼看到各类型买卖点的历史胜率和平均收益
**从而** 判断哪类信号值得信任

**验收标准：**

- [ ] 报告首屏为**信号类型汇总表**：每类信号（一/二/三类买、一/二/三类卖）× 每个窗口（5/10/20/60 交易日）的样本数、胜率、平均收益、中位数、盈亏比
- [ ] 表格支持按周期（日线/30分钟）切换，默认日线
- [ ] 胜率高于 50% 的单元格绿色标注，低于 50% 红色标注
- [ ] 展示回测元信息：股票数、区间、信号总数、剔除信号数、算法版本、计算时间
- [ ] 展示基准参照：同区间沪深300 累计涨跌幅
- [ ] 样本数 < 10 的单元格标注「样本不足，仅供参考」
- [ ] 空态：无任何已确认信号时显示「所选区间内无缠论信号」

### Story 3：下钻到具体信号

**作为** 懂缠论的伙伴
**我希望** 从统计结果下钻到每一条具体信号
**从而** 验证算法没有算错

**验收标准：**

- [ ] 汇总表任意单元格可点击进入该维度的**信号明细列表**：股票、信号时间、触发价、确认时间、各窗口实际收益
- [ ] 明细行提供「查看 K 线」，跳转个股详情页并定位到信号 K 线（复用策略监控 Story 3 的定位能力）
- [ ] 明细支持按股票筛选
- [ ] 窗口不完整的信号单独分组展示，不混入胜率计算

### Story 4：收益分布可视化

**作为** 散户
**我希望** 看到信号收益的分布形态
**从而** 直观理解"多数小赚+少数大亏"还是"多数小亏+少数大赚"

**验收标准：**

- [ ] 每类信号提供 20 日窗口收益分布直方图（区间分桶：≤-20%、-20~-10%、-10~0%、0~10%、10~20%、>20%）
- [ ] 图表遵循 `DESIGN.md` 设计系统，支持加载/空态/错误状态

## 功能需求

### 核心功能

**功能 1：历史信号重算**
- 对每只自选股、每个周期，用监控同款引擎重算完整区间 K 线的缠论结构
- 仅提取落在所选区间内的已确认信号，与功能 2 的窗口数据拼装
- 结果不写入 `t_strategy_signal`（避免污染实时信号库），存入独立回测结果表

**功能 2：窗口收益计算**
- 按股票 + 周期读取区间内收盘价序列，对每个信号计算 5/10/20/60 窗口收益
- 窗口越界（数据不足）标记 `window_incomplete`

**功能 3：统计聚合与报告存储**
- 按信号类型 × 周期 × 窗口聚合统计量（样本数/胜率/均值/中位数/盈亏比）
- 一次回测生成一个报告（含元信息与明细），报告持久化，支持查看最近 10 份历史报告
- 重新发起回测生成新报告，不覆盖旧报告

**功能 4：报告 API**
- 发起回测（SSE 进度）、查询报告列表、查询报告详情、查询明细下钻
- 结果经 Redis 缓存（报告不可变，缓存无需主动失效）

**功能 5：报告页面**
- 汇总表 + 周期切换 + 分布图 + 明细下钻 + K 线定位跳转（Story 2/3/4）
- 页面固定展示三条免责声明：不构成投资建议、生存者偏差提示、历史表现不代表未来

### 范围外（本期不做）

| 功能 | 说明 |
|------|------|
| 模拟持仓交易 / 净值曲线 | 用户已确认只要信号后统计 |
| 全市场批量回测 | 仅自选股 |
| 手续费、滑点、仓位建模 | 纯价格涨跌统计 |
| 参数调优（改笔参数/MACD 参数回测） | Phase 2，且与评估功能隔离 |
| 自定义任意起止日期 | Phase 2 |
| 多周期共振信号回测 | Phase 2，随策略监控扩展 |
| 周线/月线 | 随策略监控 Phase 2 |

## 技术约束

### 性能

- 50 只自选股 × 3 年日线 ≤120 秒；含 30 分钟 ≤300 秒（并发 ≤10，与监控任务共享并发池，回测任务低优先级排队）
- 报告详情接口 ≤1 秒（结果已持久化）

### 安全与合规

- 报告按用户隔离；回测结论页必须展示「不构成投资建议」等三条免责声明
- 文案禁止出现「回测证明可稳定盈利」类表述

### 集成

- **策略监控**：复用缠论引擎、信号类型编码、确认规则、监控配置（决定哪些股票参与回测）
- **行情模块**：读取 `t_stock_daily_quote`、`t_stock_kline_30m`；基准指数数据（沪深300 日线，若未入库需补同步）
- **前端**：个股详情页 K 线定位跳转（复用策略监控能力）

### 技术栈

- 后端：Python（Application 编排，Domain 纯函数聚合统计），APScheduler 不参与（用户手动触发）
- 持久化：MySQL（报告 + 明细）；缓存：Redis
- 前端：React + ECharts（直方图、表格徽标）

## 数据模型

| 表 | 说明 |
|----|------|
| `t_backtest_report` | 回测报告：用户、区间、周期范围、股票数、信号总数、剔除数、基准涨跌、算法版本、状态（running/done/failed）、创建时间 |
| `t_backtest_signal_detail` | 信号明细：报告 ID + 股票 + 周期 + 信号类型 + 级别 + 信号时间 + 触发价 + 5/10/20/60 窗口收益 + 窗口完整标记（唯一键：报告 ID + 股票 + 周期 + 信号时间 + 类型） |
| `t_backtest_summary` | 聚合统计：报告 ID + 周期 + 信号类型 + 窗口 → 样本数/胜率/均值/中位数/盈亏比（可由明细重算，为查询性能预聚合） |

## 风险评估

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| 回测与监控信号不一致 | 中 | 高 | 强制复用同一引擎与确认函数；一致性单元测试作为上线门禁 |
| 自选股样本太少导致统计无意义 | 高 | 中 | 样本数 < 10 明示「样本不足」；报告页提示可加入更多股票 |
| 30 分钟历史数据缺失严重 | 中 | 中 | 缺失股票在报告中标注并跳过 30 分钟统计，不影响日线 |
| 用户把胜率当作盈利保证 | 中 | 高 | 三条固定免责声明 + 基准参照 + 「历史不代表未来」文案 |
| 回测任务挤占实时计算资源 | 低 | 中 | 回测低优先级排队，与监控任务共享并发池上限 |
| 基准指数数据未入库 | 低 | 低 | 开发时验证沪深300 日线可获取性，不行则首版隐藏基准行 |

### 术语表

- **信号后统计**：不模拟买卖操作，只统计信号确认后固定窗口的价格涨跌
- **窗口不完整**：信号确认后剩余历史数据不足观察窗口，该样本不计入收益统计
- **生存者偏差**：仅用现存股票回测会高估收益的统计偏差
- **基准参照**：同区间沪深300 累计涨跌，用于排除大盘整体涨跌的干扰
