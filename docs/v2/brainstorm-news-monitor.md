# 头脑风暴：新闻监测模块

**日期**: 2026-05-11
**背景**: 基于现有 AI 股票分析平台（模块一 AI 分析 + 模块二 行情数据 + 模块三 数据工具），新增「新闻监测」模块
**核心诉求**: 爬取各大财经网站信息 → 聚合管理 → 与个股分析/事件分析联动 → 自选股新闻推送 → 每日早报

---

## 一、机会理解

### 当前系统的新闻能力现状

| 能力 | 现状 | 局限 |
|------|------|------|
| 新闻搜索 | 已有 3 个搜索引擎（Anspire/Bocha/Tavily）+ 多维度情报搜索 | **按需搜索**，用户不触发就没有 |
| 网页爬取 | 已有 BeautifulSoup 爬虫 + URL 内容提取 | 仅用于用户主动输入的 URL |
| 股票新闻 | 个股分析中新闻分析师 Agent 会调用 `get_stock_news` 工具 | 每次分析实时搜索，**不缓存、不复用** |
| 搜索缓存 | Redis 缓存搜索结果（TTL 600s） | 短暂缓存，无法积累 |

### 核心转变：从「被动搜索」到「主动监测」

```
现状：用户 → 触发分析 → 系统搜索新闻 → 使用一次 → 丢弃
目标：系统 → 定时爬取 → 聚合存储 → 按需推送 → 多次复用
```

### 竞品差异化的切入点

根据市场调研，新浪财经、同花顺、东方财富等头部平台在**资讯聚合广度**上已做到极致（新浪财经月活 1.66 亿，全网渗透率 15.46%）。我们不应做"另一个新浪财经"，而应做：

**"只推送与你相关的新闻"** — 基于自选股和已有分析记录的**个性化新闻聚合 + AI 解读**。

头部平台的新闻是广播式的（所有人看一样的内容），我们做的是窄播式的（只推和你的持仓/关注相关的）。

## 二、PM 视角：5 个功能想法

### PM-1：自选股新闻流（核心 MVP）

**想法**: 为每只自选股自动聚合相关新闻，按时间线展示，AI 自动标注利好/利空。

**为什么做**: 这是新闻监测最直接的价值 — 散户目前要逐个打开同花顺/东财看自选股新闻，我们的系统直接帮他聚合到一起。配合已有的利好/利空行业标签体系，用户一眼就知道"这条新闻是好事还是坏事"。

**关键假设**:
- 自选股数量 ≤ 30 只，每日相关新闻 ≤ 50 条，信息量可控
- AI 情感标注的准确率 ≥ 80%，用户才会信任
- 新闻来源 3-5 个即可覆盖主要信息（不需要像新浪财经那样全覆盖）

**与现有系统的协同**:
- 自选股分组数据直接复用（`t_watchlist_group` / `t_watchlist_item`）
- 情感标注复用 `MetadataExtractor` 的 sentiment 逻辑
- 新闻详情页可跳转到模块一进行事件分析

---

### PM-2：每日早报（杀手级功能）

**想法**: 每天早上 7:30 自动生成个性化投资早报，包含自选股动态 + 隔夜市场变化 + 重要财经事件 + AI 解读。

**为什么做**: 这是散户每天开盘前最核心的需求 — 快速了解"昨晚发生了什么，今天开盘会怎样"。头部平台虽有"7x24 小时快讯"，但缺乏**个性化**和**AI 解读**。我们的早报只说用户关心的股票和行业，不是泛泛而谈。

**早报结构**:
```
📊 个人投资早报 | 2026-05-11 周一
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔥 重大事件
  · 美国对伊朗实施新一轮制裁 → 利好石油石化/军工
  · 新能源汽车补贴政策延续 → 利好电力设备

📈 自选股动态
  · 宁德时代(300750)  昨收 245.30  隔夜新闻 3 条（2利好 1中性）
    → 电池出货量超预期，机构上调目标价至 280
  · 中国石油(601857)  昨收 8.92  隔夜新闻 2 条（1利好 1利空）
    → 国际油价上涨 vs 国内成品油调价预期

📋 今日关注
  · 10:00 公布 4 月 CPI 数据
  · 宁德时代股东大会

🤖 AI 观点
  综合来看，今日大盘偏暖。能源板块受地缘政治催化...
```

**关键假设**:
- 早报生成时间 ≤ 30 秒（从已缓存的新闻中聚合，不需要实时爬取）
- 用户打开早报后 5 秒内能获取核心信息
- 早报内容的个性化程度直接决定用户粘性

**与现有系统的协同**:
- 自选股行情数据复用（`t_market_quote`）
- AI 解读复用模块一的事件分析提示词模板
- 知识库历史分析可引用（"你上周分析过类似事件..."）

---

### PM-3：重大新闻自动提醒（触发式）

**想法**: 当监测到与自选股高度相关的重大新闻时，主动推送站内通知，而非被动等用户来看。

**为什么做**: 现在散户看新闻是"刷"出来的 — 刷同花顺/东财/雪球/微信公众号，信息可能刷到也可能刷不到。我们做的是"该知道的事主动告诉你"。

**触发规则**（可配置）:
- 自选股出现在新闻标题中 → 推送
- 自选股所属行业出现重大政策 → 推送
- 新闻情感标注为"重大利好"或"重大利空" → 推送
- 同一事件 3 个以上来源报道 → 标记为"热点事件"

**与现有系统的协同**:
- 推送触发后可直接跳转模块一进行 AI 事件分析（一键分析）
- 新闻与个股分析中的新闻分析师 Agent 共享数据

---

### PM-4：新闻与历史分析联动（知识增强）

**想法**: 新闻不仅是"看"的，还要与用户已有的 AI 分析和知识库产生联动。

**具体联动方式**:
- 新闻卡片下方显示"相关知识库文章"（如：看到"新能源汽车补贴政策"的新闻，下方展示"你 3 月 28 日分析过类似事件"）
- 每周自动生成本周新闻 vs 历史分析的对照摘要（"上周你分析的能源板块，本周发生了这些变化..."）
- 知识库文章底部增加"最新相关新闻"区域

**为什么做**: 这是连接"新闻监测"和"知识库"的桥梁，让新闻不只是看过了事，而是与已有认知产生化学反应。头部平台没有用户的个人分析数据，做不了这个功能 — 这是我们的**独有壁垒**。

**关键假设**:
- 新闻-文章关联的准确率 ≥ 70%（基于行业+股票代码匹配即可，不需要 LLM）
- 用户每周至少会看一次联动内容

---

### PM-5：新闻源管理与订阅配置

**想法**: 用户可以自定义关注的新闻源类型、行业、关键词。

**可配置项**:
- 关注的行业（从申万 31 个一级行业中选取）
- 关注的关键词（如"降息""制裁""财报"）
- 关注的新闻类型（政策法规 / 公司公告 / 行业动态 / 宏观经济 / 研报摘要）
- 推送频率（实时 / 早晚报 / 每日一报）

**为什么做**: 个性化是避免信息过载的关键。头部平台推的是"所有人都在看的"，我们推的是"你特别关心的"。配置粒度越细，用户越觉得"这个工具懂我"。

## 四、工程师视角：5 个功能想法

### E-1：统一新闻爬虫调度系统（核心基础）

**想法**: 基于 APScheduler 构建定时新闻爬虫调度框架。

**技术设计**:
```
┌──────────────────────────────────────────────┐
│              NewsCrawlerScheduler             │
│            (APScheduler 驱动)                 │
├──────────────────────────────────────────────┤
│  ┌─────────────┐  ┌──────────────┐           │
│  │ 财联社快讯   │  │ 东方财富资讯  │           │
│  │ (RSS/API)   │  │ (HTML爬取)   │           │
│  └──────┬──────┘  └──────┬───────┘           │
│         │                │                    │
│  ┌──────┴──────┐  ┌──────┴───────┐           │
│  │ 新浪财经    │  │ 证券时报     │           │
│  │ (RSS/API)   │  │ (RSS)       │           │
│  └──────┬──────┘  └──────┬───────┘           │
│         │                │                    │
│         └────────┬───────┘                    │
│                  ↓                            │
│  ┌───────────────────────────────┐            │
│  │     NewsPipeline              │            │
│  │  爬取 → 去重 → 清洗 → 分类    │            │
│  │  → 情感分析 → 关联股票/行业    │            │
│  │  → 入库                       │            │
│  └───────────────────────────────┘            │
└──────────────────────────────────────────────┘
```

**调度策略**:
- 交易时段（9:00-15:00）：每 15 分钟爬取一次
- 非交易时段：每 1 小时爬取一次
- 早报生成：每天 7:00 触发全天新闻聚合

**为什么重要**: 这是整个新闻监测模块的地基。没有稳定的爬虫调度，后续所有功能都是空中楼阁。

**复用现有基础设施**:
- APScheduler 已引入（requirements.txt 中有 apscheduler）
- Redis 缓存复用
- BeautifulSoup 已在用
- SearchService 多引擎搜索可复用

### E-2：新闻去重与相似度引擎

**想法**: 多源新闻聚合后，同一事件会有多篇报道，需要去重和聚合。

**技术方案**:
- **精确去重**：URL 去重（MD5 hash）
- **语义去重**：标题相似度（Jaccard 相似度 / TF-IDF 余弦相似度）
- **事件聚合**：相似新闻归为同一"事件"，选择最早或最权威的来源作为主条目

**数据模型**:
```sql
t_news_event (新闻事件/话题)
  - event_id
  - title (事件标题)
  - summary (AI生成摘要)
  - sentiment (positive/negative/neutral)
  - importance (high/medium/low)
  - industries (JSON, 关联行业)
  - stocks (JSON, 关联股票)
  - source_count (来源数量)
  - first_seen_at (首次发现时间)
  - last_seen_at (最后更新时间)

t_news_article (新闻原文)
  - article_id
  - event_id (关联事件)
  - title
  - content
  - source (来源网站)
  - url
  - published_at
  - crawled_at
  - url_hash (去重用)
```

**与现有系统的关系**:
- 新闻事件与 `t_article_stock` 共享股票关联逻辑
- 新闻事件与 `t_article_industry` 共享行业关联逻辑

---

### E-3：新闻-股票/行业自动关联引擎

**想法**: 新闻入库后自动关联到股票和行业，无需人工标注。

**技术方案**（三级匹配，从快到慢）:
1. **正则匹配**：新闻标题/内容中出现股票代码（如 300750）或标准格式"股票名（代码）"→ 直接关联
2. **名称匹配**：新闻中出现股票名称（如"宁德时代"），查 `t_stock` 表匹配 → 关联
3. **行业关键词匹配**：新闻中出现行业相关关键词（如"新能源汽车" → 电力设备/汽车），查行业-关键词映射表 → 关联
4. **LLM 兜底**（可选）：对未匹配的重要新闻，调用 LLM 提取关联行业和股票

**复用现有能力**:
- `MetadataExtractor` 的股票提取逻辑可直接复用
- `SignalExtractor` 的信号提取思路可参考

### E-4：早报生成 LangGraph 工作流

**想法**: 早报不是简单的新闻列表拼接，而是一个 LangGraph 驱动的 AI 编排流程。

**工作流设计**:
```
START
  → collect_news (收集过去24小时新闻，按自选股/行业/重要性分组)
  → collect_portfolio_status (收集自选股行情变化)
  → collect_knowledge_context (检索知识库相关历史分析)
  → generate_briefing (LLM生成早报，包含：重大事件摘要/自选股动态/今日关注/AI观点)
  → save_briefing (持久化早报到数据库)
  → END
```

**优势**:
- 复用 LangGraph 框架（项目已引入，团队熟悉）
- 早报内容来自本地数据库（已缓存的新闻），不依赖实时爬取
- 可根据用户偏好定制（关注哪些行业、推送频率等）

### E-5：统一新闻源抽象层（Crawler Interface）

**想法**: 定义统一的新闻源接口，不同新闻网站只需实现该接口即可接入。

**接口设计**:
```python
class BaseNewsProvider(ABC):
    """新闻源统一抽象"""

    @abstractmethod
    async def fetch_latest(self, count: int) -> list[RawNewsItem]:
        """获取最新新闻"""

    @abstractmethod
    async def fetch_by_stock(self, stock_code: str, count: int) -> list[RawNewsItem]:
        """按股票代码获取新闻"""

    @abstractmethod
    async def fetch_by_keyword(self, keyword: str, count: int) -> list[RawNewsItem]:
        """按关键词搜索新闻"""
```

**已实现的新闻源**（可直接适配）:
- Tavily Search Provider → 适配为 `TavilyNewsProvider`
- Anspire Search Provider → 适配为 `AnspireNewsProvider`
- Bocha Search Provider → 适配为 `BochaNewsProvider`

**新增的新闻源**（需开发）:
- 财联社快讯（API/RSS）
- 东方财富资讯（HTML 爬取）
- 新浪财经 RSS
- 证券时报 RSS
- 巨潮资讯网（公告类）

**为什么重要**: 统一抽象使得新增新闻源的成本极低（只需实现一个 Provider），且与现有 `BaseSearchProvider` 架构一致。

## 五、Top 5 优先级排序

### 优先级评估标准

| 维度 | 权重 | 说明 |
|------|------|------|
| 核心价值 | 40% | 是否解决用户最痛的问题？ |
| 可验证速度 | 30% | 能否快速上线验证？ |
| 差异化潜力 | 20% | 头部竞品是否容易复制？ |
| 协同价值 | 10% | 与现有模块的联动程度 |

### Top 5 排序

---

#### #1 🥇 每日早报（PM-2 + D-2 + E-4）

**核心价值**: 解决散户每天开盘前最核心的信息需求 — "今天该关注什么"
**差异化**: 头部平台的早报是广播式的，我们的是**个性化**的（基于自选股 + 历史分析）
**验证速度**: MVP 只需要定时任务 + 新闻聚合 + LLM 生成，2-3 周可出 demo
**协同价值**: 极高 — 直接拉动模块一（早报中的事件可一键分析）、模块二（自选股行情）、知识库（历史分析引用）

**关键假设需验证**:
1. 早报的个性化程度（自选股相关度）≥ 80%，用户才会觉得有价值
2. 早报生成时间 ≤ 30 秒（从本地缓存聚合）
3. 用户打开早报后，至少会点击一个"分析"或"查看详情"按钮

**MVP 范围**:
- 后端：APScheduler 定时任务（7:00）+ LangGraph 早报生成工作流
- 前端：早报展示页面（卡片式布局）
- 新闻源：复用现有 3 个搜索引擎，暂不新增爬虫

---

#### #2 🥈 自选股新闻流（PM-1 + D-1 + D-4 + E-3）

**核心价值**: 解决"想看自选股的新闻，还得一个个打开东财/同花顺"的痛点
**差异化**: 所有自选股的新闻聚合到一处，AI 自动标注利好/利空
**验证速度**: 依赖新闻爬虫基础设施，3-4 周可出 demo
**协同价值**: 高 — 新闻直接与自选股行情、个股分析联动

**关键假设需验证**:
1. 每只自选股每日相关新闻 ≤ 10 条，总量可控
2. AI 情感标注用户接受度 ≥ 80%（标注错了用户会吐槽）
3. 新闻-股票自动关联的准确率 ≥ 85%

**MVP 范围**:
- 后端：新闻爬虫 + 去重 + 股票关联引擎
- 前端：自选股页面增加新闻列 + 独立新闻时间线页面
- 新闻源：3-5 个核心源（财联社/东财/新浪）

---

#### #3 🥉 重大新闻自动提醒（PM-3 + D-5）

**核心价值**: 解决"重要新闻刷不到"的问题
**差异化**: 头部平台靠人工编辑推送，我们靠 AI 自动判断重要性
**验证速度**: 依赖新闻爬虫 + 关联引擎，可复用 #1 和 #2 的基础设施
**协同价值**: 高 — 推送后可一键触发模块一事件分析

**关键假设需验证**:
1. 每日推送 ≤ 5 条（多了就是噪音）
2. AI 判断"重大"的准确率 ≥ 70%（误判过多会被关掉通知）
3. 用户收到推送后的点击率 ≥ 30%

**MVP 范围**:
- 后端：重要性评分算法 + 推送触发逻辑
- 前端：铃铛通知 + 新闻摘要 Drawer

---

#### #4 新闻与知识库联动（PM-4）

**核心价值**: 让新闻不只是"看"，还与已有分析产生关联
**差异化**: **独有壁垒** — 头部平台没有用户的个人分析数据，做不了这个功能
**验证速度**: 依赖新闻关联引擎，可在 #2 之后快速实现
**协同价值**: 极高 — 打通新闻 ↔ 知识库的闭环

**关键假设需验证**:
1. 新闻-文章关联的匹配准确率 ≥ 70%
2. 用户每周至少会看一次联动内容
3. 联动展示不影响新闻浏览体验（不能太重）

---

#### #5 新闻源管理与订阅配置（PM-5 + E-5）

**核心价值**: 让用户自定义关注范围，避免信息过载
**差异化**: 个性化程度高于头部平台
**验证速度**: 相对独立，可并行开发
**协同价值**: 中 — 主要是配置管理，不直接影响其他模块

**关键假设需验证**:
1. 用户愿意花时间配置（散户的时间很宝贵）
2. 默认配置就能满足 80% 用户需求（减少配置负担）
3. 配置变更后效果即时可见

## 七、风险与注意事项

| 风险 | 概率 | 应对 |
|------|------|------|
| 新闻网站反爬（IP 封禁、验证码） | 高 | 控制爬取频率（≥ 15 分钟间隔）；优先用 RSS/API；多 IP 轮换（云服务器） |
| 版权合规（直接展示原文） | 中 | 只展示标题+摘要（≤ 200字），点击跳转原文链接；早报内容为 AI 生成总结 |
| AI 情感标注不准（用户不信任） | 中 | MVP 阶段用简单规则（关键词匹配），后续迭代引入 LLM；标注可手动修正 |
| 新闻量过大导致信息过载 | 中 | 默认只推自选股相关+重大事件；推送频率可配；去重聚合减少重复 |
| 数据库存储压力 | 低 | 新闻正文仅存摘要（≤ 500字），原文链接跳转；超过 30 天的新闻自动归档 |
