# Product Requirements Document: AI 智能分析 & 投研知识库（v2）

**版本**: 2.0
**日期**: 2026-05-11
**说明**: 本文档基于实际代码实现重写，反映模块一的真实功能。原始需求文档保留在 `docs/ai-analysis-prd.md`。

---

## 执行摘要

面向 A 股散户的 AI 智能分析与投研知识库模块，包含两套独立的 AI 分析系统：

1. **事件分析（系统 A）**：对话式事件分析，用户输入新闻/事件描述（文本/URL/文件），AI 自动预处理后生成结构化分析报告
2. **个股分析（系统 B）**：多 Agent 辩论式个股深度分析，模拟投研团队协作，输出操作建议和风险评估

两套系统共享同一个知识库，分析结果均可保存归档，形成可全文检索的个人投研知识库。

---

## 与原计划的核心差异

| 维度 | 原计划 (v3.3) | 实际实现 (v2.0) |
|------|---------------|-----------------|
| 分析模式 | 单一模式：选类型→输问题→出结果 | 两套独立系统：对话式事件分析 + 多Agent个股分析 |
| 技术架构 | 单次 LLM 调用 + 流式输出 | LangGraph 工作流 + 13个Agent协作 |
| 交互方式 | 单次输入表单 | ChatGPT 对话式（事件分析）+ 向导式（个股分析） |
| 输入方式 | 纯文本 | 文本 + URL链接 + 文件上传（PDF/Word） |
| 搜索能力 | 无互联网搜索 | 多引擎搜索（Anspire/Bocha/Tavily）+ 网页爬取 |
| 预处理 | 无 | LangGraph 管线：输入分类→搜索→加载→检索→总结 |
| 个股分析 | 不存在 | 全新功能：13个Agent辩论架构（快速/深度两种模式） |

## 用户故事 & 验收标准

### Story 1：对话式事件分析

**作为** A 股散户
**我希望** 通过对话式界面输入事件描述（文本/URL/文件），让 AI 自动搜索、分析并生成结构化报告
**从而** 快速了解事件对 A 股各行业的影响

**验收标准：**

- [ ] 页面采用 ChatGPT 对话式布局，左侧为会话列表，右侧为对话区域
- [ ] 支持创建、切换、删除多个会话
- [ ] 每个会话可选事件类型：地缘政治 / 政策法规 / 财报季报 / 产业链分析 / 其他
- [ ] 支持三种输入方式：
  - 直接输入文本描述
  - 输入 URL 链接（AI 自动爬取网页内容）
  - 上传文件（支持 PDF / Word / 纯文本）
- [ ] AI 自动执行预处理管线：
  1. **输入分类**：LLM 判断输入是 URL / 文件 / 文本，以及是否需要联网搜索
  2. **联网搜索**（如需）：调用多搜索引擎获取相关信息
  3. **内容加载**：爬取网页 / 解析文件 / 直接使用文本
  4. **知识库检索**：搜索个人历史分析，避免重复分析
  5. **上下文总结**：LLM 将所有信息整合为分析上下文
- [ ] 预处理完成后，根据事件类型选择对应提示词模板，调用 LLM 流式生成分析
- [ ] 分析结果实时流式显示，包含思考过程（reasoning）和正式内容（content）
- [ ] 分析完成后自动生成：
  - **标题**（≤15 字）
  - **摘要**（≤80 字，结论导向）
  - **行业标签**（从申万 31 个一级行业中提取，标注利好/利空）
  - **关联股票**（提取代码和名称，标注利好/利空）
- [ ] 用户可编辑标题和摘要
- [ ] 用户可调整行业标签和股票关联
- [ ] 确认后保存到知识库

### Story 2：个股快速分析

**作为** A 股散户
**我希望** 输入一只股票代码，快速获得 AI 的分析意见
**从而** 在 1 分钟内了解这只股票是否值得关注

**验收标准：**

- [ ] 页面提供股票搜索输入框，支持代码和名称搜索
- [ ] 系统检查该股票近期是否已有分析，如有则提示"X天前已分析过"
- [ ] 选择「快速分析」模式
- [ ] AI 执行 2 步分析流程：
  1. **分析师阶段**：技术面分析师 + 基本面分析师（共 2 位，顺序执行）
  2. **快速决策**：综合两位分析师结论，给出操作建议
- [ ] 分析过程中实时显示每个 Agent 的状态和进度
- [ ] 分析完成后展示：
  - 操作建议（买入/卖出/持有）
  - 目标价 + 止损价
  - 置信度评分
  - 各分析师简要报告
- [ ] 分析结果自动保存，可在"分析记录"页面回看

### Story 3：个股深度分析

**作为** A 股散户
**我希望** 对一只股票进行全面深度分析，模拟真实投研团队的协作
**从而** 获得更全面、更客观的投资决策参考

**验收标准：**

- [ ] 选择「深度分析」模式
- [ ] AI 执行 4 阶段、13 个 Agent 的协作分析流程：

**第一阶段：四位分析师（analysts）**
- [ ] 技术面分析师：读取K线形态、趋势、支撑压力位
- [ ] 基本面分析师：分析财务数据、估值、盈利能力
- [ ] 新闻分析师：搜索并分析最新新闻和公告
- [ ] 情绪分析师：分析市场情绪和资金流向
- [ ] 每位分析师可调用工具获取数据（实时行情 / 历史K线 / 财务数据 / 新闻）
- [ ] 工具调用采用三级容错：本地数据库 → Tushare → BaoStock
- [ ] 每位分析师完成后生成独立报告

**第二阶段：投资辩论（debate）**
- [ ] 看多研究员（Bull）与看空研究员（Bear）交替辩论，默认 2 轮
- [ ] 研究主管总结辩论要点，输出综合研究报告

**第三阶段：交易决策（trader）**
- [ ] 交易决策官综合所有分析，给出操作建议
- [ ] 输出：操作方向（买入/卖出/持有）、目标价、止损价、预期收益

**第四阶段：风险辩论（risk）**
- [ ] 激进派、保守派、中立派三方交替辩论，默认 2 轮
- [ ] 风险裁决官最终裁决，输出风险评分
- [ ] 信号提取器提取关键交易信号

**结果展示：**
- [ ] 操作建议卡片：操作方向 + 目标价 + 止损价 + 预期收益 + 置信度
- [ ] 风险评分 SVG 仪表盘
- [ ] 各分析师详细报告（可展开/收起）
- [ ] 投资辩论时间线（Bull/Bear 交锋过程）
- [ ] 风险评估详情（激进/保守/中立观点对比）
- [ ] 完整报告（Markdown 格式，可滚动查看）

## 功能需求

### 系统 A：事件分析引擎

**功能 A1：LangGraph 预处理管线**

事件分析不是简单的"输入 → LLM"，而是经过 LangGraph 工作流驱动的多步预处理：

```
用户输入
  ↓
agent_classify（LLM判断输入类型：URL/文件/文本，是否需要搜索）
  ↓ [条件路由]
web_search（多引擎互联网搜索，如需）
  ↓
load（加载内容：网页爬取 / 文件解析 / 直接使用文本）
  ↓
retrieve（检索知识库历史文章）
  ↓
summarize_context（LLM总结上下文）
  ↓
进入 LLM 分析阶段（根据事件类型选择提示词模板）
```

**功能 A2：多搜索引擎**

搜索服务支持 3 个引擎，按优先级自动切换：
1. Anspire（优先）
2. Bocha
3. Tavily

搜索功能包括：
- 通用搜索：根据关键词搜索互联网
- 股票新闻搜索：搜索特定股票的最新新闻（中文优先，时效过滤）
- 多维度情报搜索：最新新闻 / 市场分析 / 风险预警 / 公告 / 财报 / 行业

**功能 A3：内容加载**

支持三种输入的处理：
- **URL**：通过 BeautifulSoup 爬取网页内容，提取正文
- **文件**：支持 PDF、Word、纯文本文件的解析
- **文本**：直接使用用户输入

**功能 A4：五套提示词模板**

| 模板 | 适用类型 | 分析重点 |
|------|----------|----------|
| 地缘政治 | geopolitical | 军工/能源/贵金属/航运 |
| 政策法规 | policy | 直接覆盖行业、上下游传导 |
| 财报季报 | earnings | 个股业绩对行业估值影响 |
| 产业链分析 | supply_chain | 逐层追踪上下游传导（最多5层），含产业链传导表 |
| 通用 | other | 标准六段式分析 |

所有模板统一输出：事件背景 / 影响逻辑 / 受益行业 / 受损行业 / 推荐关注股票 / 风险提示。
产业链分析额外输出：产业链传导表。
分析末尾同步输出 TITLE（≤15字）和 SUMMARY（≤80字）。

### 系统 B：个股分析引擎

**功能 B1：LangGraph 多 Agent 工作流**

个股分析采用 LangGraph 驱动的多 Agent 协作架构，支持两种模式：

**快速模式**：
```
技术面分析师 → 基本面分析师 → 快速决策 → END
```

**深度模式**：
```
技术面分析师 → 基本面分析师 → 新闻分析师 → 情绪分析师
  → 看多研究员 ←→ 看空研究员（辩论循环，2轮）
  → 研究主管
  → 交易决策官
  → 激进派 ←→ 保守派 ←→ 中立派（辩论循环，2轮）
  → 风险裁决官
  → 信号提取器
  → END
```

**功能 B2：Agent 工具调用**

分析师 Agent 可通过 LangChain Tool 调用以下工具：
- `get_stock_quote`：获取实时行情
- `get_stock_history`：获取历史K线数据
- `get_stock_financial`：获取财务指标
- `get_stock_news`：获取最新新闻

每个工具内部实现三级数据容错：本地 MySQL 数据库 → Tushare API → BaoStock API。

**功能 B3：分析记录持久化**

每次分析完成后，结果持久化到 `t_stock_analysis`（主表）和 `t_stock_analysis_detail`（Agent 详情表），包含：
- 分析模式（quick/full）、状态、当前阶段
- 标题、摘要、完整内容
- 操作建议（买入/卖出/持有）、目标价、止损价、置信度、风险评分
- 每个Agent 的独立报告、思考步骤、辩论数据

### 共享功能

**功能 C1：元数据提取**

`MetadataExtractor` 从 AI 分析内容中自动提取：
- **股票**：标准格式匹配 → 代码匹配 → 名称匹配（三级扫描），附带 sentiment 标注
- **行业**：解析器提取 → 申万标准校验 → LLM 兜底

**功能 C2：会话管理**

事件分析和个股分析共享会话系统：
- `t_chat_session`：会话表，支持 `event_analysis` 和 `stock_analysis` 两种类型
- `t_chat_message`：消息表，存储角色（user/assistant/system）、内容、思考步骤、Agent 数据等

**功能 C3：知识库全文搜索**

- 搜索范围：标题 + 摘要 + 正文 + 行业标签 + 股票代码
- 技术方案：MySQL FULLTEXT + ngram 中文分词

## 技术架构

### LangGraph 工作流

**事件分析工作流（AnalysisGraph）**
- State: `AnalysisState`（InputState → WorkingState → OutputState 三层结构）
- 节点：agent_classify / web_search / load / retrieve / summarize_context
- 工具：web_scraper / file_parser / web_search

**个股分析工作流（StockAnalysisGraph）**
- State: `StockAnalysisState`
- 节点：4 分析师 + 2 辩论者 + 研究主管 + 交易员 + 3 风险辩论者 + 风险裁决官 + 信号提取器 + 快速决策
- 条件路由：根据 `analysis_mode`（quick/full）分流、辩论循环控制
- 工具：stock_data_toolkit（4 个 LangChain Tool）

### AIService 统一抽象

`AIService` 封装所有 LLM 调用：
- `stream_chat`：流式对话，支持 reasoning_content（推理模型）
- `generate_title_and_summary`：非流式标题摘要生成
- `tool_call`：非流式 function calling
- `stream_chat_with_tools`：流式 function calling

支持 DeepSeek / GLM 等 OpenAI 兼容 API。

### 数据模型

| 表 | 说明 |
|----|------|
| `t_analysis_article` | 事件分析文章主表（标题/摘要/正文/事件类型/行业/股票关联） |
| `t_article_industry` | 文章-行业关联（含 chain_level 和 sentiment） |
| `t_article_stock` | 文章-股票关联（含 sentiment） |
| `t_chat_session` | 会话表（支持 event_analysis / stock_analysis 类型） |
| `t_chat_message` | 消息表（角色/内容/思考步骤/Agent数据） |
| `t_stock_analysis` | 个股分析主表（模式/状态/决策/目标价/风险评分） |
| `t_stock_analysis_detail` | 个股分析详情（每Agent一条：报告/思考步骤/辩论数据） |
