## 我们在做一个什么产品？

一句话：**帮A股散户把"看新闻 → 找股票 → 深度分析 → 判断买卖"这条链路，在一个工具里跑通。**

现在散户的状态是：
- 看到一条财经新闻，不知道会影响哪些股票
- 想深入了解一只股票，缺少系统化的分析方法
- 分析过的东西，下次就忘了，认知无法积累
- 每天要手动盯着几十只股票，又累又容易漏

我们的产品解决的就是这四个问题。

## 产品由三个模块组成

```
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
│      模块一           │    │      模块二           │    │      模块三           │
│  AI 智能分析          │───▶│  行情数据展示          │◀───│  数据与工具           │
│  & 投研知识库         │    │  & 个股详情           │    │  & 数据同步           │
└──────────────────────┘    └──────────────────────┘    └──────────────────────┘
  看懂新闻，深度分析个股       找到股票，看懂行情       管理数据源，同步行情
```

三个模块互相打通：
- 模块一分析文章里的股票，点击直接弹出K线侧边栏
- 模块一个股分析中，分析师Agent自动调用模块二的行情数据
- 模块三同步的行情数据，支撑模块二的K线图和财务数据展示
- 模块二自选股列表，展示股票详情和行业对比

## 模块一：AI 智能分析 & 投研知识库

### 和原计划的差异

原计划是一套"选类型 → 输入 → 出结果 → 保存"的单次分析流程。实际实现扩展为**两套独立的 AI 分析系统**，覆盖更广的使用场景。

### 系统 A：事件分析（对话式）

> 解决"看到新闻，不知道影响哪只股票"的问题

**使用方式**：
1. 打开事件分析页面，类似 ChatGPT 的对话界面
2. 选择事件类型：地缘政治 / 政策法规 / 财报季报 / 产业链分析 / 其他
3. 输入事件描述（支持文本、URL链接、文件上传）
4. AI 自动预处理：判断输入类型 → 搜索互联网（如需）→ 加载内容 → 检索知识库 → 总结上下文
5. 根据事件类型选择最优提示词模板，AI 流式生成结构化分析
6. 分析完成后展示：自动生成的标题和摘要、行业标签（利好/利空）、关联股票（利好/利空）
7. 确认后保存到知识库

**核心技术**：
- LangGraph 工作流引擎驱动预处理管线
- 多搜索引擎（Anspire / Bocha / Tavily）自动切换
- 网页爬取（BeautifulSoup）+ 文件解析（PDF/Word）
- 5套提示词模板，按事件类型自动匹配
- SSE 流式输出，实时展示思考过程和分析内容

### 系统 B：个股深度分析（多 Agent 辩论）

> 解决"想深入了解一只股票，缺少系统化分析"的问题

这是原计划中不存在的全新功能。采用**多 Agent 辩论架构**，模拟真实投研团队的协作方式。

**使用方式**：
1. 输入股票代码或名称
2. 选择分析模式：
   - **快速分析**：2位分析师 → 快速决策，约 1 分钟
   - **深度分析**：13 个 Agent 协作，约 3-5 分钟
3. 实时查看每个 Agent 的分析进度和报告
4. 获得最终操作建议（买入/卖出/持有）+ 目标价 + 止损价 + 风险评估

**深度分析流程（13 个 Agent）**：

```
第一阶段：四位分析师（并行）
  技术面分析师 ──── 读懂K线形态、趋势、支撑压力位
  基本面分析师 ──── 读懂财务数据、估值、盈利能力
  新闻分析师   ──── 搜索并分析最新新闻和公告
  情绪分析师   ──── 分析市场情绪和资金流向

第二阶段：投资辩论（2轮）
  看多研究员 ←→ 看空研究员（交替辩论）
      ↓
  研究主管（总结辩论要点）

第三阶段：交易决策
  交易决策官（综合所有信息，给出操作建议）

第四阶段：风险辩论（2轮）
  激进派 ←→ 保守派 ←→ 中立派（三方辩论）
      ↓
  风险裁决官（最终裁决，输出风险评分）
```

**每个 Agent 的能力**：
- 分析师 Agent 可以调用工具获取实时行情、历史K线、财务数据、新闻
- 工具调用采用三级容错：本地数据库 → Tushare → BaoStock
- 辩论 Agent 基于前序分析结果进行对抗性论证

**分析结果展示**：
- 操作建议卡片（买入/卖出/持有 + 目标价 + 止损价 + 预期收益）
- 置信度评分 + 风险评分（SVG 仪表盘）
- 各分析师详细报告（可展开/收起）
- 投资辩论时间线
- 风险评估详情
- 完整报告（Markdown 格式）

### 知识库

保留原计划的核心功能，支持三种视图：

| 视图 | 说明 |
|------|------|
| 行业视图 | 按申万一级行业分组浏览文章 |
| 时间线视图 | 所有文章按日期倒序排列 |
| 股票视图 | 按自选股筛选相关文章 |

新增：文章卡片展示利好/利空行业标签、利好/利空股票关联。

## 模块二：行情数据展示 & 个股详情

### 和原计划的差异

核心功能（K线图、自选股、行业对比）均已实现，同时增加了多数据源支持和批量行情获取。

### 核心功能

**1. 股票详情页**
- 顶部价格卡：最新价、涨跌幅、成交量、成交额
- K线图（ECharts）：支持分时 / 日K / 周K / 月K 四种周期
- 技术指标：MA5/MA10/MA20（默认）+ MACD / KDJ（可切换开关）
- 底部标签页：基本信息 / 财务数据 / 同行对比 / 相关分析

**2. 全局股票抽屉**
- 任何页面点击股票代码，右侧弹出抽屉查看行情
- 不打断当前操作，关闭后回到原页面

**3. 自选股管理**
- 分组管理（创建/重命名/删除分组）
- 自选股列表展示：代码、名称、最新价、涨跌幅、行业、自选日、自选价、自选涨幅
- 交易时段内 30 秒自动刷新行情

**4. 行业对比**
- 左侧申万 31 个一级行业导航
- 右侧行业股票表格：涨跌幅、PE、PB、营收、净利润、净利润增长率
- 支持按任意列排序

**5. 股票搜索**
- 支持代码和名称模糊搜索
- 搜索结果展示：股票名称 + 代码 + 今日涨跌幅

### 技术亮点

| 功能 | 说明 |
|------|------|
| 多数据源支持 | Tushare / AKShare / BaoStock 三种数据源可配置 |
| 批量行情 | 腾讯财经 + 新浪财经双源容错，30秒缓存 |
| 分时数据 | 腾讯 → 新浪 → TwelveData 三级容错 |
| 技术指标 | MA / MACD / KDJ 由后端计算并持久化 |
| 相关分析标签 | 个股详情页底部展示知识库中涉及该股的历史分析文章 |

## 模块三：数据与工具

### 和原计划的差异

原计划为"缠论策略监控"模块。实际实现为**数据管理与同步面板**（本模块聚焦数据采集和工具管理）。缠论策略监控与历史回测已独立实现（spec 009），详见 `docs/v2/strategy-monitor-prd-v2.md` 与 `docs/v2/backtest-prd-v2.md`。

### 核心功能

**1. 数据同步面板**
- 选择数据源：Tushare / AKShare / BaoStock
- 选择同步类型：基础信息 / 实时行情 / 日K线 / 财务数据
- SSE 流式展示同步进度（已处理/成功/失败数量）
- 同步历史记录，支持重试失败任务

**2. 数据源配置**
- 管理 API Key（Tushare 等）
- API Key 使用 Fernet 加密存储，展示时脱敏
- 支持启用/禁用、优先级排序

## 技术架构

### 后端
- **框架**：Python FastAPI + SQLAlchemy 2.0（async）
- **工作流引擎**：LangGraph（驱动 AI 分析流程）
- **LLM**：统一抽象层（AIService），支持 DeepSeek / GLM 等 OpenAI 兼容接口
- **数据源**：AKShare / Tushare / BaoStock 三源可切换
- **搜索引擎**：Anspire / Bocha / Tavily 多引擎容错
- **数据库**：MySQL（17张表）
- **缓存**：Redis（自动降级，Redis不可用时不影响主流程）

### 前端
- **框架**：React 18 + TypeScript + Vite
- **UI**：Ant Design 5（Stripe 风格设计系统）
- **图表**：ECharts 6（K线图）
- **状态管理**：Zustand（9个 Store）
- **流式交互**：EventSource（SSE）
- **Markdown 渲染**：react-markdown + remark-gfm

### DDD 分层架构
```
后端：Router → Application(UseCase) → Domain(Service/Entity) → Infrastructure(DB/AI/Cache)
前端：Page → Application(Hook) → Service(API) → Domain(Type/Constant)
```

## 产品边界（不做什么）

| 不做的事 | 原因 |
|---------|------|
| 自动交易/下单 | 只是分析工具，最终决策权在用户 |
| 实时行情（Level 2） | 免费数据源15-30分钟延迟，散户够用 |
| AI自动抓取新闻推送 | 用户主动输入，保证分析质量 |
| 复杂财务分析 | 普通散户用不到杜邦分析等高级指标 |
| 港股/美股 | 先聚焦A股做好 |
| 多人协作 | 个人工具，不做团队功能 |

## 与原计划的核心差异总结

| 维度 | 原计划 | 实际实现 |
|------|--------|----------|
| 模块一分析方式 | 单次输入 → 输出 | 两套系统：对话式事件分析 + 多Agent个股分析 |
| 分析架构 | 单 LLM 调用 | LangGraph 工作流 + 13个Agent辩论 |
| 输入方式 | 纯文本 | 文本 + URL + 文件上传 |
| 搜索能力 | 无 | 多引擎互联网搜索（3个引擎容错） |
| 模块三定位 | 缠论策略监控 | 数据与工具面板 + 缠论监控/回测（spec 009，已实现） |
| 认证 | 未规划 | 完整用户认证系统 |
| 数据源 | AKShare 单源 | Tushare/AKShare/BaoStock 三源 |
| 行情获取 | 单一方式 | 腾讯+新浪+TwelveData 多级容错 |
