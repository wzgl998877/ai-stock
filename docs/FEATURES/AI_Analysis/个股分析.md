第二部分：深度分析执行与结果页 · 优化指令
界面： 深度分析 · 执行与结果页
当前核心缺陷：

右侧展示区未随左侧阶段切换，始终只显示第一阶段（分析师阶段）内容。

“查看详细推理”展开后未输出全量文本，存在截断。

底部决策与风险区所有角色均为“就绪”，无实际产出。

报告内容直接堆砌，缺乏结构化提炼。

优化后定位： “分析过程监控与结论阅读台”——阶段联动，摘要前置，全量可查，决策结论充实。

1. 【最高优先级】右侧内容与左侧阶段联动
1.1 阶段-内容映射
前端维护 currentStage 状态变量，由后端实际执行进度驱动。右侧展示内容严格按阶段切换：

currentStage	右侧渲染内容
analyst	四位分析师卡片（技术、基本面、新闻、情绪）
debate	辩论区：看多研究员、看空研究员、研究主管
decision	交易决策区：交易决策官、目标价、置信度、决策依据
risk	风险评估区：激进派、保守派、中立派、风险裁决官
1.2 阶段同步机制

后端必须通过接口（轮询或WebSocket）提供当前真实执行阶段状态。

前端不得自主提前推进，左侧步骤条高亮与右侧内容渲染均依赖该状态。

若后端为一次性全流程执行，需一次性返回各阶段完成状态及对应数据，前端依次切换。

1.3 已完成阶段回溯

已完成阶段内容自动折叠为一行：“分析师阶段已完成 ✓ · 点击回看”。

点击可展开完整内容，但不影响当前阶段的主显示区。

当前阶段始终占据右侧主视野。

2. 【最高优先级】“查看详细推理”必须展示全量
2.1 全量渲染要求

点击“查看详细推理”必须渲染该分析师本轮输出的完整所有文本，不得有任何字符截断。

展开容器必须有独立滚动条，确保超长输出可以完整阅读。

2.2 端到端排查清单

后端：确认生成内容全量返回，流式分片完整送达。

存储：数据库存储时未做长度限制截断（如TEXT类型足够）。

前端：请求全量内容接口，展开组件渲染全量数据而非仅预览片段。

2.3 交互规范

默认状态：显示“核心结论摘要”行 + “> 查看详细推理”。

展开状态：显示完整推理内容，可滚动，入口文字变为“∨ 收起详细推理”。

收起后回到默认，阅读位置重置到顶部。

3. 报告区结构化展示升级
3.1 独立角色卡片
每位分析师/研究员渲染为独立卡片，内部结构自上而下：

角色标识行：头像图标 + 角色名称 + 状态标签（已完成/分析中/就绪）+ 时间戳

结论摘要行（加粗）：从原始输出中提取首句核心判断或关键数据

详情入口：> 查看详细推理（默认折叠）

展开详情区：完整原始推理，独立滚动

当 currentStage === 'debate' 时，采用左右分栏。

左栏：看多研究员内容，绿色边框；右栏：看空研究员内容，红色边框。

所有数字（价格、涨幅、百分比、财务指标等）自动识别并加粗、使用主题色高亮。

4. 底部决策与风险评估区填充
4.1 阶段依赖

若 currentStage 未到达 decision 或 risk，底部角色显示暗色头像剪影 + 提示：“待前置阶段完成后触发”。

到达对应阶段后，头像翻转为亮色，填充实际内容卡片。

4.2 每位角色必须输出观点

每个决策/评估角色卡片内，必须包含其观点摘要，不得仅显示“已完成”或时间戳。

若后端暂时无输出，可展示兜底文案：“分析结果生成中，请稍后回看”，但保留卡片框架与角色名。

4.3 风险评分可视化

风险评分配合色阶条：

0-30：绿色（低风险）

31-60：黄色（中等）

61-80：橙色（中高）

81-100：红色（高风险）

同时展示色阶条 + 数值 + 风险等级文字。

4.4 无效值处理

目标价、置信度、风险评分仅在有效范围内展示，但若有值即使为0也可显示（由后端决定），前端不做额外过滤。

5. 左侧流程区微调
5.1 步骤条

顶部横向步骤条：“分析师阶段 → 投资辩论 → 交易决策 → 风险评估”。

当前阶段高亮+呼吸光效，已完成打勾，未开始置灰。切换过渡动画0.3s。

5.2 节点状态图标统一

已完成：绿色✓ + 时间戳

失败：红色✗ + 时间戳

分析中：蓝色微旋转动画 + “分析中”

就绪：灰色时钟 + “就绪”

5.3 已完成阶段折叠

当前阶段之前的所有阶段，收缩为一行“XX阶段已完成 ✓”，点击展开明细。

6. 其他细节
6.1 “停止分析”按钮

点击弹出确认：“确认停止当前分析？已生成部分将保留。”

确认后停止后端任务，前端保留已完成内容。

6.2 错误信息前端展示规范

不直接展示后端返回的红色报错原文（如error码、技术栈信息）。

失败的分析维度以灰色卡片展示，内容显示“该维度分析暂未完成”。原始错误可记录日志但不在前端渲染。

6.3 合规提示

页面底部固定：“本工具仅供投研参考，不构成任何投资建议”。

最终完整流程体验：
用户在入口页感知多Agent引擎能力，选择“深度分析”并输入标的，点击启动后进入执行监控台。四大阶段依序推进，右侧内容随阶段自动切换，分析师结论、多空辩论、交易决策、风险评估层层递进。每个结论摘要前置、完整推理可展开、关键数据高亮。分析结束后，一份结构化、可读、可信的完整投研报告呈现眼前。

二、存档机制：全程自动保存
2.1 触发时机

用户点击“开始分析”时，后端创建一条分析记录，状态为“进行中”。

分析执行过程中，每完成一个阶段（分析师阶段完成、投资辩论完成、交易决策完成、风险评估完成），后端立即将该阶段的完整数据写入这条记录。

用户点击“停止分析”或页面意外断开时，已完成的阶段数据不丢失。

2.2 存档内容
每条分析记录包含以下字段：

字段	说明
记录ID	唯一标识
标的名称/代码	如“沃格光电（603773）”
分析模式	快速分析 / 深度分析
分析状态	进行中 / 已完成 / 已停止
创建时间	点击开始分析的时间
最后更新时间	最近一次写入阶段数据的时间
各阶段数据	每个阶段的完整内容，含每个Agent的原始输出全量文本和时间戳
2.3 注意：与V4.0“全量查看”的一致性
存档时必须写入每个Agent的完整输出文本，确保用户从分析记录点进去展开“查看详细推理”时，依然能拉取到全量内容。

四、从记录进入查看：替换执行页的初始化逻辑
4.1 点击“查看详情”后

4.2 页面渲染

左侧步骤条：根据存档数据中哪些阶段有数据，标记“已完成✓”；当前最新有数据的阶段高亮。

“停止分析”按钮：若记录状态为“进行中”，按钮保留并可点击继续停止后端任务；若记录状态为“已完成”或“已停止”，按钮置灰或隐藏。

即：从“查看详情”进入，如果分析还没跑完，等同于“接续监控”。
