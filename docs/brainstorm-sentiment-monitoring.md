# 舆情检测功能头脑风暴 — AI Stock 平台增量功能探索

**日期**: 2026-05-11
**背景**: 用户希望在现有三模块（AI事件分析 / 行情数据 / 策略监控）基础上，增加舆情检测能力，探索与现有产品的联动方式

---

## 一、机会理解

### 当前产品状态

现有三个模块形成"看新闻→找股票→判断买卖"的闭环，但存在一个关键缺口：**信息输入端完全依赖用户手动触发**。

- 模块一：用户主动输入事件描述 → AI分析 → 保存知识库
- 模块二：用户主动搜索/点击 → 看行情
- 模块三：系统自动监控缠论信号 → 用户被动查看

**舆情检测要解决的核心问题**：让信息从"被动等用户输入"变为"主动推送给用户"，填补"我可能遗漏了重要信息"这个恐惧。

### 与现有边界的关系

> 项目宪章明确"AI自动抓取新闻"不在MVP范围，但"舆情检测"≠"自动抓取"。

关键区分：
- **自动抓取**：无差别爬取全量新闻 → 信息过载 → 不做
- **舆情检测**：基于用户自选股/关注行业定向监控 → 信号过滤 → **可做**

定位为**"为你的自选股和关注行业定制的舆情雷达"**，而非通用新闻聚合器。

## 三、优先级排序（Top 5）

按以下权重评分：核心价值（40%）+ 验证速度（30%）+ 差异化潜力（30%）

### 第1名：PM-1 自选股舆情卡片

**总分：9.2/10**

- **核心价值**：自选股是用户最高频访问的页面，在此叠加舆情信息，投入产出比最高
- **验证速度**：可先手动mock数据验证UI交互，2天可出Demo
- **差异化**：同花顺/东财有新闻但不是"为你自选股定制"的舆情聚合，定位清晰
- **联动路径**：
  ```
  自选股列表（模块二/三）
    → 每只股票旁显示舆情热度标签
    → 点击热度标签展开新闻摘要
    → 新闻摘要右下角"AI分析"按钮 → 跳转模块一
  ```
- **关键假设**：
  1. 用户愿意每天查看自选股列表的舆情标签（而非觉得是噪音）
  2. 3条新闻足够帮助用户判断是否需要深入了解
  3. 免费搜索API的调用量能满足自选股舆情查询需求

### 第2名：PM-3 舆情信号 + 缠论信号共振提醒

**总分：8.8/10**

- **核心价值**：真正实现三模块深度联动——技术面信号（模块三）+ 消息面信号（舆情）+ AI分析（模块一）三位一体
- **验证速度**：需要模块三信号计算+舆情数据都就绪，约1-2周
- **差异化**：市场上极少有工具同时提供技术信号+舆情共振，强差异化
- **联动路径**：
  ```
  缠论买点信号出现（模块三）
    + 同期该股舆情正面热升（舆情检测）
    → 推送"强关注"提醒
    → 用户点击 → 同时看到K线箭头（模块二）+ 相关新闻（舆情）+ 历史分析（模块一）
  ```
- **关键假设**：
  1. 舆情方向与技术信号方向一致时，信号可信度确实更高（需回测验证）
  2. 用户能理解"共振"概念且不会盲从
  3. 舆情情感分析准确率足够（>70%）才有参考价值

### 第3名：D-1 K线图上的舆情气泡

**总分：8.5/10**

- **核心价值**：技术面+消息面在同一视图叠加，可视化联动效果最直观
- **验证速度**：ECharts markPoint/markLine已有成熟API，3天可出Demo
- **差异化**：现有工具K线上只有技术指标，几乎没有标注新闻事件的
- **联动路径**：
  ```
  K线图（模块二）
    → 时间轴上标注舆情气泡（正/中/负 颜色区分）
    → 鼠标悬停显示事件摘要
    → 点击气泡 → 展开该事件的模块一AI分析文章（如有）
  ```
- **关键假设**：
  1. 舆情事件能精确关联到K线的某一天（时间对齐精度足够）
  2. 气泡不会过于密集导致K线图可读性下降（需设置显示阈值）
  3. 用户习惯在K线图上看消息面信息

### 第4名：PM-5 每日舆情早报

**总分：8.3/10**

- **核心价值**：用最低用户操作成本（零操作）获取最高价值信息——开盘前5分钟掌握全局
- **验证速度**：可先做静态版本（每天定时生成一次），1周可出MVP
- **差异化**：同花顺/东财有资讯推送但不是"围绕你的自选股定制"的
- **联动路径**：
  ```
  每日8:30定时任务
    → 聚合用户自选股+关注行业昨日至今舆情
    → AI生成摘要（复用模块一AI能力）
    → 推送到首页 + 站内通知
    → 早报中的每条事件可直接触发模块一深度分析
  ```
- **关键假设**：
  1. 用户确实会在开盘前打开产品看早报（而非9:30直接看行情）
  2. AI生成的舆情摘要质量足够好（不遗漏重大事件，不多报噪音）
  3. 每日一次的聚合搜索API调用量在成本可接受范围内

### 第5名：E-2 AI情感分析Agent

**总分：8.0/10**

- **核心价值**：所有舆情功能的技术基础——没有情感分析，舆情只是新闻列表；有了情感分析，舆情才变成"信号"
- **验证速度**：复用已有LangGraph架构，新增1-2个节点，1周可出原型
- **差异化**：情感分析本身不差异化，但与缠论信号+行业知识库的联动组合是差异化的
- **联动路径**：
  ```
  新闻文本输入
    → LangGraph情感分析Agent
    → 输出：情感方向（正/中/负）+ 情感强度 + 影响行业 + 关联股票
    → 写入舆情数据表
    → 驱动PM-1/PM-3/D-1等上层功能
  ```
- **关键假设**：
  1. LLM对中文财经新闻的情感分析准确率足够（>75%）
  2. 情感分析成本可控（可复用现有LLM调用，增量成本低）
  3. 单条新闻的情感方向能代表对股票的影响方向（有时正面新闻反而导致下跌）

## 四、实施路径建议

### Phase 0：舆情数据基础（1-2周）

建立舆情数据获取和存储的基础能力：

```
后端新增：
├── domain/
│   ├── entities/sentiment.py          # 舆情实体
│   ├── value_objects/sentiment_type.py # 情感方向枚举
│   ├── repositories/sentiment_repo.py # 舆情仓库接口
│   └── services/sentiment_analyzer.py # 情感分析领域服务
├── application/
│   ├── use_cases/fetch_sentiment.py   # 拉取舆情用例
│   └── dtos/sentiment_dto.py          # 舆情DTO
├── infrastructure/
│   ├── search/sentiment_fetcher.py    # 基于现有search provider的舆情拉取
│   ├── db/models.py                   # 新增 t_stock_sentiment 表
│   └── repositories/mysql_sentiment_repo.py
└── routers/sentiment.py               # 舆情API路由
```

数据库新增表：
```sql
CREATE TABLE t_stock_sentiment (
    id SERIAL PRIMARY KEY,
    stock_code VARCHAR(10) NOT NULL,
    source VARCHAR(50) NOT NULL,       -- 数据来源（tavily/bocha/anspire）
    title VARCHAR(200),                -- 新闻标题
    summary TEXT,                       -- 新闻摘要
    url VARCHAR(500),                  -- 原文链接
    sentiment VARCHAR(10),             -- positive/neutral/negative
    sentiment_score DECIMAL(3,2),      -- 情感强度 0-1
    mentioned_industries JSON,         -- 提及的行业
    published_at TIMESTAMP,            -- 发布时间
    fetched_at TIMESTAMP DEFAULT NOW(),
    -- 审计字段
    create_time TIMESTAMP DEFAULT NOW(),
    update_time TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_sentiment_code_date ON t_stock_sentiment(stock_code, published_at DESC);
```

### Phase 1：MVP联动（2-3周）

基于Phase 0的数据基础，实现Top 5中的前3个：

1. **自选股舆情卡片**（PM-1）→ 模块二/三自选股列表增强
2. **K线舆情气泡**（D-1）→ 模块二K线图增强
3. **AI情感分析Agent**（E-2）→ 技术底座

### Phase 2：深度联动（2-3周）

4. **舆情+缠论信号共振**（PM-3）→ 三模块深度联动
5. **每日舆情早报**（PM-5）→ 首页统一视图增强

### Phase 3：体验优化（持续）

- 定向舆情订阅（PM-4）
- 舆情时间轴面板（D-2）
- 舆情-行情关联分析（E-3）
- 实时推送（E-5）

## 五、风险与对齐要点

### 需要确认的产品方向

1. **舆情检测 ≠ 自动抓取新闻**：是否认同"基于自选股/关注行业定向监控"的定位？还是想做更广泛的新闻聚合？
2. **信息密度控制**：每只股票每天显示多少条舆情？多了是噪音，少了怕遗漏
3. **AI分析的触发时机**：舆情新闻是否自动触发AI分析？还是只做推荐，用户手动触发？
4. **成本控制**：舆情拉取+情感分析的API调用频率和成本上限

### 技术风险

| 风险 | 概率 | 应对 |
|------|------|------|
| 搜索API调用量超限 | 中 | 增量去重 + Redis缓存 + 调用频率限制 |
| LLM情感分析准确率不足 | 中 | 先用规则辅助（关键词匹配）+ 人工标注小样本校准 |
| 舆情数据与K线时间对齐偏差 | 低 | 允许±1天的容差，模糊匹配 |
| 舆情信息过载导致用户关闭功能 | 中 | 提供舆情开关 + 每股每日最多3条 + 热度阈值过滤 |
