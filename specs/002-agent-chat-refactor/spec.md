# Feature Specification: Agent 对话式投研助手

**Feature Branch**: `002-agent-chat-refactor`
**Created**: 2026-04-20
**Status**: Draft
**Input**: 将 AI 分析模块从表单式单次分析重构为 Agent 对话式投研助手，支持思维链展示、多轮对话、Agent 自主搜索决策

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 对话式分析交互 (Priority: P1)

用户打开 AI 分析页面，看到类似 ChatGPT/DeepSeek 的对话界面。在底部输入框输入问题（如"美国制裁伊朗对哪些行业有影响"），系统展示思维链过程（"正在判断输入类型..."、"正在搜索相关资讯..."、"正在分析..."），然后流式输出分析结果。分析完成后，用户可以在同一个对话中继续追问（如"交通运输行业具体哪些股票受影响？"），系统基于上一轮的上下文进行回答。

**Why this priority**: 这是最核心的交互变革——从"填表→出结果"升级为"对话→思考→追问"。没有这个，其他功能都无从谈起。

**Independent Test**: 可以通过打开分析页面、输入一个问题、看到思维链+流式回答、然后追问一个问题来完整测试。即使没有搜索和知识库检索，纯对话交互也能独立运行。

**Acceptance Scenarios**:

1. **Given** 用户在分析页面, **When** 输入"美国制裁伊朗对哪些行业有影响"并点击发送, **Then** 页面展示思维链步骤（判断类型→搜索→分析），然后流式展示分析结果
2. **Given** 第一轮分析已完成, **When** 用户继续输入"那交通运输行业具体哪些股票受影响？", **Then** 系统基于上一轮分析的上下文生成回答，不丢失之前的内容
3. **Given** AI 正在流式输出中, **When** 用户点击"停止生成", **Then** 输出立即停止，已输出的内容保留在对话中
4. **Given** 用户输入了一个 URL 链接, **When** 发送后, **Then** 思维链显示"正在爬取网页内容..."，爬取完成后基于网页内容进行分析

---

### User Story 2 - 思维链实时展示 (Priority: P2)

在 AI 分析过程中，用户能实时看到后台正在执行的每个步骤，而不是面对空白等待。每个步骤以简短文字呈现（如"正在判断输入类型..."、"搜索到 3 篇相关报道..."、"找到 2 篇历史分析..."、"正在分析事件影响..."），步骤完成后打勾或折叠。

**Why this priority**: 思维链是用户体验的关键提升——消除"黑盒等待"的焦虑感，让用户理解 AI 在做什么。P1 的对话交互可以不依赖思维链独立工作，但思维链让体验质变。

**Independent Test**: 输入任意问题，观察思维链步骤是否按序展示、是否实时更新、完成后是否正确折叠。即使 Agent 只做了简单的文本分析（没有搜索），思维链也应展示"检测到纯文本输入，直接分析"这类信息。

**Acceptance Scenarios**:

1. **Given** 用户发送了分析请求, **When** 后端开始处理, **Then** 前端实时展示当前执行步骤（如"正在判断输入类型..."）
2. **Given** 后端完成了搜索步骤, **When** 搜索到结果, **Then** 思维链更新为"搜索到 3 篇相关报道"并标记完成
3. **Given** 分析完成, **When** 所有步骤执行完毕, **Then** 思维链区域折叠，仅显示步骤摘要，主内容区展示分析结果

---

### User Story 3 - Agent 自主搜索决策 (Priority: P3)

用户输入任意文本（不限于 URL），Agent 自主判断是否需要搜索外部信息。例如输入"美国和伊朗目前的战争情况，可能会影响哪些行业"，Agent 自动识别这涉及时事热点，先搜索最新信息，再结合搜索结果进行分析。如果输入的是已知的静态信息（如"2024年Q3宁德时代财报分析"），Agent 判断不需要搜索，直接分析。

**Why this priority**: 这是 Agent 智能化的核心——从"用户必须提供 URL 或文本"升级为"Agent 自己决定需要什么信息"。但它依赖 P1（对话交互）和 P2（思维链）先就位，否则用户看不到搜索过程。

**Independent Test**: 输入一个涉及时事热点的问题，观察 Agent 是否自动触发搜索并展示搜索结果。输入一个不需要搜索的问题，观察 Agent 是否跳过搜索直接分析。

**Acceptance Scenarios**:

1. **Given** 用户输入"美国和伊朗目前的战争情况，可能会影响哪些行业", **When** Agent 判断涉及时事, **Then** 自动搜索相关信息，思维链显示搜索过程和结果
2. **Given** 用户输入"帮我分析新能源汽车产业链", **When** Agent 判断为通用知识, **Then** 可选择不搜索直接分析，或搜索补充最新数据
3. **Given** Agent 搜索失败或无结果, **When** 外部搜索服务不可用, **Then** 降级为基于 LLM 自身知识分析，思维链提示"搜索服务暂时不可用，基于已有知识分析"

---

### User Story 4 - 会话管理 (Priority: P4)

用户可以创建多个分析会话，每个会话保持独立的对话历史。侧边栏显示历史会话列表，支持切换、重命名、删除会话。刷新页面后会话和对话历史不丢失。

**Why this priority**: 多会话是产品化的必要功能，但技术上依赖 P1 的对话模型和数据库持久化。MVP 阶段可以先支持单会话（不持久化），后续迭代加入多会话管理。

**Independent Test**: 创建两个不同的分析会话，分别进行对话，切换会话后对话历史正确显示。

**Acceptance Scenarios**:

1. **Given** 用户在分析页面, **When** 点击"新建会话", **Then** 创建空白对话，侧边栏新增一条记录
2. **Given** 用户有两个会话, **When** 从会话 A 切换到会话 B, **Then** 对话区显示会话 B 的历史消息
3. **Given** 用户刷新页面, **When** 页面重新加载, **Then** 之前的会话和对话历史仍然存在

---

### Edge Cases

- 用户在 AI 流式输出过程中发送新消息 → 停止当前输出，保留已输出内容，然后处理新消息
- 用户输入极长的文本（>5000字） → 提示过长或自动截断
- 搜索服务超时或不可用 → 降级为纯 LLM 分析，思维链提示降级原因
- 用户在思维链展示阶段关闭页面 → 未持久化的会话状态丢失，下次可新建会话
- 多轮对话超过上下文窗口限制 → 自动截断早期对话，保留最近 N 轮
- 用户只输入 URL 不加任何文字 → 直接爬取 URL 内容并分析
- 用户连续快速发送多条消息 → 只处理最新一条，之前的自动取消

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供对话式交互界面，包含消息列表区和底部输入框，支持文本和 URL 输入
- **FR-002**: 系统必须在 AI 分析过程中实时展示思维链步骤，每一步完成后更新状态（进行中→完成→折叠）
- **FR-003**: 系统必须支持多轮对话，用户可以在分析结果基础上继续追问，上下文不丢失
- **FR-004**: 系统必须支持用户停止正在进行的 AI 输出（保留已输出内容）
- **FR-005**: Agent 必须自主判断输入是否需要搜索外部信息，而非依赖硬编码规则
- **FR-006**: 当用户输入 URL 时，系统必须自动爬取网页内容并基于内容进行分析
- **FR-007**: 系统必须搜索知识库中的历史分析文章，将相关结果作为上下文注入
- **FR-008**: 当搜索或爬取失败时，系统必须降级为基于 LLM 自身知识的分析，并在思维链中提示降级原因
- **FR-009**: 系统必须支持会话持久化，刷新页面后对话历史不丢失
- **FR-010**: 系统必须支持多个独立的分析会话，每个会话保持独立的对话上下文
- **FR-011**: 多轮对话超过上下文窗口时，系统必须自动截断早期对话，保留最近的上下文
- **FR-012**: 分析结果必须继续支持 Markdown 渲染和结构化展示（标题、摘要、行业标签）

### Key Entities

- **ChatSession**: 分析会话，包含标题、创建时间、最后活跃时间。一个会话包含多条消息
- **ChatMessage**: 对话消息，包含角色（user/assistant）、内容、思维链步骤、创建时间。属于某个会话
- **ThinkingStep**: 思维链步骤，包含步骤名称、状态（进行中/完成/失败）、描述、时间戳。属于某条 assistant 消息

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户发送问题后，1 秒内看到第一个思维链步骤（消除空白等待感）
- **SC-002**: 分析结果流式输出，首 token 延迟不超过 3 秒（包含预处理时间）
- **SC-003**: 用户能在分析完成后立即追问，第二轮回答基于第一轮的完整上下文
- **SC-004**: Agent 对时事类问题的判断准确率 > 80%（自动触发搜索 vs 直接分析）
- **SC-005**: 刷新页面后，会话和对话历史 100% 恢复
- **SC-006**: 思维链步骤数量 ≥ 3（至少展示判断、搜索/加载、分析三个阶段）

## Assumptions

- MVP 阶段搜索能力依赖外部搜索 API（如 Tavily / SerpAPI），不自建搜索引擎
- 文件上传功能暂不纳入本次重构范围（保留 file_parser 预留接口）
- 会话持久化使用现有 MySQL 数据库，不引入新的存储服务
- 多轮对话的上下文窗口限制由 LLM 模型的 max_tokens 决定，默认保留最近 10 轮对话
- 用户身份暂使用默认 user_id（"default"），认证系统不在本次范围内
- 移动端适配不在本次范围内，仅考虑桌面端体验
- 前端仍使用 React + Ant Design + Zustand 技术栈，不引入新的 UI 框架
- 事件类型选择（地缘政治/政策法规/财报/产业链）保留，但由 Agent 辅助判断而非用户手动选择
