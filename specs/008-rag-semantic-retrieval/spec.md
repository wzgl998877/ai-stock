# Feature Specification: RAG 语义检索增强

**Feature Branch**: `008-rag-semantic-retrieval`
**Created**: 2026-05-19
**Status**: Draft
**Input**: 基于 `docs/v2/rag-prd.md` PRD，为 AI 股票分析平台引入 RAG（检索增强生成）功能，用向量语义检索替代关键词匹配，覆盖 LangGraph retrieve 节点、事件雷达知识库联动、事件去重引擎、Agent 上下文注入 4 个场景。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 事件分析上下文检索增强 (Priority: P1)

用户使用事件分析功能时，AI 需要从知识库中检索历史分析作为上下文。当前检索基于关键词匹配，经常召回不相关的文章。引入向量语义检索后，retrieve 节点能找到语义真正相关的历史分析，即使措辞完全不同（如输入"新能源补贴影响"能关联到"光伏政策扶持分析"）。当向量检索无结果时，自动回退到关键词检索确保不遗漏。

**Why this priority**: 直接影响 AI 分析报告质量——retrieve 节点是 LangGraph 事件分析管线中的核心环节，上下文质量决定了最终分析报告的深度和价值。这是 ROI 最高的改造点。

**Independent Test**: 触发一次事件分析（如输入"国际油价突破 85 美元"），对比改造前后 retrieve 节点返回的 3 篇历史文章的相关性。可人工评估相关性评分是否提升。

**Acceptance Scenarios**:

1. **Given** 用户触发事件分析，**When** retrieve 节点执行检索，**Then** 返回的 top 3 历史文章在语义上与当前分析主题相关（而非仅关键词重叠）
2. **Given** 知识库中存在语义相关但措辞不同的历史文章，**When** retrieve 节点执行检索，**Then** 这些文章能被成功召回
3. **Given** 向量检索未找到任何相关结果，**When** 回退机制触发，**Then** 系统使用关键词检索返回结果，分析流程不中断
4. **Given** 向量服务不可用（模型加载失败等），**When** retrieve 节点执行，**Then** 自动降级到关键词检索，用户无感知

---

### User Story 2 - 事件雷达知识库精准联动 (Priority: P2)

用户查看影响事件时，事件卡片上展示"你之前分析过的相关文章"。当前关联依赖行业+股票交集和词频重叠，精准度不够。引入语义相似度后，系统能实现"这条事件和你 3 月分析过的新能源政策相关度 85%"这样的精准关联，这是区别于头部竞品的独有壁垒。

**Why this priority**: 这是事件雷达 PRD 中承诺的"独有壁垒"功能，头部竞品无法复制的差异化能力。依赖 Story 1 的基础设施（embedding 服务）。

**Independent Test**: 创建一条影响事件，查看其"知识库关联"区域展示的历史文章，验证语义相关度计算是否准确，以及无结果时是否回退到行业+股票交集匹配。

**Acceptance Scenarios**:

1. **Given** 一条影响事件入库，**When** 系统计算其与知识库文章的关联，**Then** 返回语义最相关的 top 3 历史文章，并附带相关度百分比
2. **Given** 事件与文章的语义相似度低于阈值（< 0.7），**When** 语义匹配无结果，**Then** 系统回退到行业+股票交集匹配，确保总能给出关联建议
3. **Given** 知识库中存在与事件语义相关但未涉及相同行业/股票的文章，**When** 语义匹配执行，**Then** 仍能被成功召回（突破行业交集的限制）

---

### User Story 3 - 事件去重引擎增强 (Priority: P3)

事件采集管线每 10 分钟采集一批财经信息，同一事件常有多个来源的报道。当前去重依赖 URL 精确匹配和 TF-IDF 标题相似度，对"不同措辞描述同一事件"的情况识别不足。新增语义 embedding 相似度后，去重引擎能更精准地合并同一事件的不同报道。

**Why this priority**: 提高事件采集质量，减少重复事件对用户的噪音。优先级低于前两个故事，因为现有去重机制已基本可用。

**Independent Test**: 向采集管线注入两条描述相同事件但措辞不同的新闻（如"央行降息 25 个基点"和"人民银行下调基准利率 0.25%"），验证是否被正确合并为同一事件。

**Acceptance Scenarios**:

1. **Given** 两条新闻描述同一事件但措辞不同，**When** 去重管线执行，**Then** 语义相似度 ≥ 0.85，被合并为同一事件
2. **Given** 两条新闻涉及不同事件但主题相近，**When** 去重管线执行，**Then** 语义相似度 < 0.85，不被合并
3. **Given** 去重管线执行顺序，**When** 处理一条新闻，**Then** 依次经过 URL hash → TF-IDF → 语义相似度三个阶段，URL 精确匹配优先级最高

---

### User Story 4 - Agent 上下文注入增强 (Priority: P4)

用户使用个股深度分析时，13 个 Agent 协作完成分析。当前 Agent 只能通过工具调用获取行情和新闻数据，无法参考知识库中的历史分析。引入向量检索后，新闻分析师 Agent 可额外获取语义相关的历史分析摘要作为参考，提升分析建议的依据深度。

**Why this priority**: 提升个股分析质量，但改造涉及 LangGraph 工作流内部节点，复杂度较高。优先级最低，可在前三个故事验证 RAG 价值后再实施。

**Independent Test**: 触发一次个股深度分析（如宁德时代），对比改造前后新闻分析师 Agent 的分析报告中是否引用了历史分析的相关结论。

**Acceptance Scenarios**:

1. **Given** 个股深度分析的新闻分析师 Agent 执行，**When** 知识库中存在该股票的相关历史分析，**Then** Agent 额外获得 top 3 相关历史分析摘要（总长 ≤ 2000 字）
2. **Given** 知识库中无相关历史分析，**When** Agent 执行，**Then** 不注入额外上下文，Agent 行为与改造前完全一致
3. **Given** 注入的上下文超过 2000 字限制，**When** 系统截断上下文，**Then** 保留最相关的内容，不占用过多 token 预算

---

### Edge Cases

- **向量服务启动失败**：模型加载失败时，所有检索场景自动降级到关键词模式，不阻塞系统启动和任何业务流程
- **知识库为空（新用户）**：向量检索返回空结果，回退到关键词检索（也为空），不影响用户体验
- **文章保存时 embedding 生成失败**：文章正常保存到主数据库，日志记录 embedding 失败，不阻塞保存流程
- **ChromaDB 数据文件损坏**：向量数据可从主数据库全量重建索引，不丢失任何业务数据
- **历史文章无 embedding**：只对新文章生成 embedding，历史文章暂不迁移。retrieve 节点和关联匹配在向量无结果时回退到关键词检索

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在文章保存到知识库时，自动生成文本的语义向量并存储到向量数据库
- **FR-002**: 系统必须在事件采集入库时，自动生成事件标题+摘要的语义向量
- **FR-003**: LangGraph retrieve 节点必须使用语义检索替代关键词检索，返回 top 3 语义最相关的历史文章
- **FR-004**: 当语义检索无结果时，所有场景必须自动回退到关键词检索，确保不遗漏
- **FR-005**: 事件雷达必须使用语义相似度计算影响事件与知识库文章的关联度，返回 top 3 相关文章及相关度百分比
- **FR-006**: 事件去重引擎必须在现有 URL hash + TF-IDF 基础上，新增语义 embedding 相似度去重
- **FR-007**: 个股分析的新闻分析师 Agent 必须能获取语义相关的历史分析上下文（top 3，≤ 2000 字）
- **FR-008**: 语义相似度阈值必须可配置（retrieve 节点默认 0.7，去重引擎默认 0.85）
- **FR-009**: 向量服务不可用时，系统必须优雅降级到关键词检索，所有业务流程不中断
- **FR-010**: 文章 embedding 生成失败不得阻塞文章保存流程，主数据库写入优先
- **FR-011**: 文章更新时必须覆盖对应的向量数据
- **FR-012**: 系统启动时必须预加载语义模型，加载完成前所有检索使用关键词模式

### Key Entities

- **Article Embedding**: 知识库文章的语义向量，关联 article_id，包含标题+摘要的向量表示和元数据（标题、股票代码、行业、事件类型）
- **Event Embedding**: 影响事件的语义向量，关联 event_id，包含标题+摘要的向量表示和元数据（标题、关联股票、关联行业）
- **Retrieval Result**: 检索结果实体，包含文章/事件 ID、语义相似度分数、元数据

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 语义检索的召回率 ≥ 85%（在 50 组测试 query 上对比关键词检索）
- **SC-002**: 语义检索的准确率 ≥ 80%（top-5 结果中相关文章的占比）
- **SC-003**: retrieve 节点返回的上下文相关性评分 ≥ 4.0/5（人工评估 20 次事件分析）
- **SC-004**: 语义检索响应时间 ≤ 500ms（知识库规模 ≤ 10,000 篇文章时）
- **SC-005**: 文章保存延迟增加 ≤ 100ms（因 embedding 生成而额外增加的时间）
- **SC-006**: 向量服务不可用时，系统降级到关键词检索无感知延迟，所有功能正常可用

## Assumptions

- **用户无感知**：RAG 改造对前端完全透明，API 契约不变，用户唯一能感知到的是检索结果更精准
- **仅新文章生成 embedding**：历史文章暂不做全量迁移，MVP 阶段通过回退机制覆盖历史文章的检索
- **本地部署模型**：语义模型在服务器本地运行，不向外部 API 发送用户数据，保障数据安全
- **数据量可控**：知识库文章量级在数百~数千篇，嵌入式向量数据库可满足性能和容量需求
- **复用现有 DDD 架构**：向量检索能力在 Domain 层定义抽象接口，Infrastructure 层实现，不破坏现有分层
- **依赖现有事件雷达基础设施**：Story 2 和 Story 3 依赖事件雷达模块已完成的采集管线和数据表
- **CPU 推理满足需求**：无需 GPU，CPU 推理在 ≤ 500ms 延迟目标内可接受
