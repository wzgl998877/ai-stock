# Feature Specification: 股票详情页与行情数据展示

**Feature Branch**: `006-stock-detail-kline`
**Created**: 2026-04-30
**Status**: Draft
**Input**: User description: "完成模块二行情数据展示，在知识库/问答/自选股等界面点击股票跳转到详情页，展示K线、分时等基本信息，类似东方财富/同花顺界面"

---

## 需求合理性分析

### 需求背景
当前用户在模块一（AI分析）阅读文章后，发现推荐股票需要切换到同花顺/东方财富查看行情，导致分析流程被打断。用户希望在产品内完成"发现股票 → 查看行情 → 判断决策"的完整闭环。

### 合理性评估

| 维度 | 评估 | 说明 |
|------|------|------|
| 用户价值 | ✅ 高 | 消除产品内外的上下文切换，将分析-决策链路留在同一工具内 |
| 与PRD对齐 | ✅ 高度一致 | 与 `docs/market-data-prd.md` 的Story 1/2/3/4/5完全吻合 |
| 模块联动 | ✅ 关键路径 | 模块一→模块二→模块三的跳转是产品闭环的核心 |
| 技术可行性 | ✅ 可行 | 数据通过AKShare获取，图表通过成熟图表库实现，有缓存机制 |
| MVP范围 | ✅ 适度 | Phase 1聚焦核心功能（K线+财务+搜索+自选股），Phase 2扩展行业对比等 |

### 核心交付范围（Phase 1 / MVP）

1. **个股详情页**：K线图（分时/日K/周K/月K切换）+ 顶部价格卡 + 指标开关
2. **财务数据标签**：PE / PB / 营收 / 净利润 4个核心指标
3. **相关分析标签**：个股关联的模块一历史分析文章列表
4. **模块一联动**：文章内股票代码点击 → 侧边栏抽屉展示K线（不跳页）
5. **股票搜索**：代码/名称模糊搜索，实时下拉匹配
6. **自选股管理**：默认3个分组，支持新增/改名/增删股票
7. **行业导航**：申万31个一级行业 → 行业股票对比列表

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从模块一分析文章查看股票K线 (Priority: P1)

用户正在阅读AI分析文章，文章正文或摘要中出现了股票名称/代码（如"宁德时代 300750"），用户点击该股票名称，在当前页面右侧以抽屉/侧边栏形式展示该股票的日K线图和基本信息，无需离开当前阅读页面。

**Why this priority**: 这是模块一→模块二联动的核心路径，直接消除用户"读文章→切软件看行情"的上下文切换成本。如果仅实现这一个故事，就能让分析流程不再被打断，产生即时价值。

**Independent Test**: 可独立测试：在模块一任意分析文章中点击股票代码，侧边栏立即弹出K线图，显示股票名称、当前价格、涨跌幅、日K线（含MA均线+成交量），且不影响左侧文章的阅读位置。

**Acceptance Scenarios**:

1. **Given** 用户在阅读模块一的AI分析文章，**When** 文章正文中出现可点击的股票名称/代码，**Then** 鼠标悬停时显示下划线提示可点击
2. **Given** 用户点击文章中的股票代码，**When** 系统响应，**Then** 在当前页面右侧以抽屉/侧边栏形式展示该股行情，左侧文章内容保持原位不变
3. **Given** 侧边栏已打开，**When** 用户查看K线图，**Then** 默认展示日K线，包含MA5/MA10/MA20均线和成交量柱，顶部显示股票名称、代码、当前价格、今日涨跌幅
4. **Given** 侧边栏已打开，**When** 用户点击"展开完整页面"按钮，**Then** 跳转到该股完整详情页（新页面或路由切换）

---

### User Story 2 - 个股完整详情页查看技术+基本面信息 (Priority: P1)

用户进入某只股票的完整详情页，在一个页面内看到该股的技术面（K线图+技术指标）和基本面（财务数据）信息，并能查看与该股票相关的历史AI分析文章。

**Why this priority**: 这是模块二的核心页面，散户判断一只股票是否值得关注的全部信息集中在此。K线形态+估值指标+相关分析三位一体，支撑用户做出综合决策。

**Independent Test**: 可独立测试：直接访问某股票代码的详情页URL，页面完整加载K线图、顶部价格卡、底部标签页（基本信息/财务数据/同行对比/相关分析），且K线图支持周期切换和指标开关。

**Acceptance Scenarios**:

1. **Given** 用户进入个股详情页，**When** 页面加载完成，**Then** 顶部显示股票名称、代码、当前价格、涨跌额/涨跌幅、今日成交量/成交额
2. **Given** 用户查看K线图区域，**When** 切换周期标签，**Then** 支持分时/日K/周K/月K四种周期自由切换，默认日K
3. **Given** 用户查看K线图，**When** 操作鼠标，**Then** 支持拖动平移和滚轮缩放；鼠标悬停时显示当根K线的开盘价、最高价、最低价、收盘价、成交量
4. **Given** 用户查看指标区，**When** 操作指标开关，**Then** MA（5/10/20日）和成交量默认开启；MACD和KDJ可通过开关自由开启/关闭
5. **Given** 用户点击底部"财务数据"标签，**When** 切换到该标签，**Then** 展示PE（市盈率TTM）、PB（市净率）、最近一年营收、最近一年净利润及同比增长率；涨跌用红绿色标注
6. **Given** 用户点击底部"相关分析"标签，**When** 切换到该标签，**Then** 展示模块一知识库中所有涉及该股的历史分析文章（标题+摘要≤80字+保存日期），按日期倒序排列；点击文章跳回模块一知识库定位展开
7. **Given** "相关分析"标签下没有历史文章，**When** 切换到该标签，**Then** 显示"暂无相关分析"提示，不显示引导按钮
8. **Given** 用户在个股详情页，**When** 点击右上角"加入自选股"按钮，**Then** 弹出分组选择（重仓股/观察股/备选股），选择后该股票加入对应分组

### User Story 3 - 搜索股票并进入详情页 (Priority: P2)

用户想要查看某只特定股票的行情，但不在任何分析文章中，通过在搜索框输入股票名称或代码快速定位并进入详情页。

**Why this priority**: 这是用户主动发现股票的主要入口。虽然价值略低于模块一联动（因为联动是更自然的场景），但搜索是独立使用模块二的必要能力。

**Independent Test**: 可独立测试：在搜索框输入任意股票代码或名称的前几个字符，下拉列表实时显示匹配结果，点击结果直接进入详情页。

**Acceptance Scenarios**:

1. **Given** 用户在模块二页面，**When** 在顶部搜索框输入2个或以上字符，**Then** 实时展示下拉匹配列表，每项显示股票名称+代码+今日涨跌幅
2. **Given** 用户输入模糊名称，**When** 系统搜索，**Then** 支持模糊匹配（如输入"宁德"可匹配"宁德时代"）
3. **Given** 用户点击搜索结果中的某只股票，**When** 点击，**Then** 直接进入该股个股详情页
4. **Given** 搜索无匹配结果，**When** 用户查看下拉列表，**Then** 显示"未找到相关股票，请检查代码或名称"

---

### User Story 4 - 自选股分组管理 (Priority: P2)

用户将关注的股票按投资状态分组管理（如重仓股/观察股/备选股），方便快速查看和跟踪。

**Why this priority**: 自选股是模块三（策略监控）的前置依赖，也是用户日常看盘的核心入口。分组的目的是区分不同关注程度的股票。

**Independent Test**: 可独立测试：在自选股管理界面，可创建分组、重命名分组、将股票加入/移出分组，列表中显示每只股票的价格和涨跌幅。

**Acceptance Scenarios**:

1. **Given** 用户进入自选股页面，**When** 查看分组，**Then** 默认展示3个分组：重仓股、观察股、备选股
2. **Given** 用户需要更多分组，**When** 点击新增分组，**Then** 可创建自定义分组（名称最长10字），每个用户最多10个分组
3. **Given** 用户需要修改分组名，**When** 点击重命名，**Then** 可修改分组名称（默认分组不允许删除）
4. **Given** 用户删除一个自定义分组，**When** 确认删除，**Then** 若分组内有股票，提示"该分组有X只股票，删除后将移入观察股"
5. **Given** 用户查看自选股列表，**When** 浏览列表，**Then** 每行显示股票名称+代码+当前价格+今日涨跌幅+所属行业+缠论信号灯状态
6. **Given** 用户点击列表中的某只股票，**When** 点击，**Then** 跳转该股个股详情页
7. **Given** 用户需要移除某只股票，**When** 点击移除按钮，**Then** 该股票从当前分组移除

---

### User Story 5 - 按行业浏览股票并横向对比 (Priority: P3)

用户想了解某个行业内所有股票的整体表现，通过横向对比涨跌幅、估值、业绩，找到行业内更优质的标的。

**Why this priority**: 行业对比是进阶功能，用户价值低于直接看个股K线，但能帮助用户建立行业视角，发现被低估的标的。

**Independent Test**: 可独立测试：点击左侧行业导航中的某个行业，主区域展示该行业股票对比表，可按任意列排序。

**Acceptance Scenarios**:

1. **Given** 用户在模块二页面，**When** 查看左侧导航，**Then** 显示申万一级行业列表（共31个），只显示行业名称
2. **Given** 用户点击某个行业，**When** 系统响应，**Then** 主区域展示该行业股票综合对比表，包含：股票名称+代码、今日涨跌幅、PE、PB、近一年营收、近一年净利润、净利润同比增长率
3. **Given** 用户查看对比表，**When** 点击任意列标题，**Then** 按该列升序/降序切换排序；默认按今日涨跌幅降序排列
4. **Given** 用户点击对比表中的某只股票行，**When** 点击，**Then** 跳转到该股个股详情页
5. **Given** 用户查看行业页面，**When** 查看页面顶部，**Then** 显示该行业今日整体涨跌幅（行业内所有股票涨跌幅均值）

---

### Edge Cases

- **股票停牌/退市**：K线图显示最后有效交易日数据，价格卡显示"停牌"状态，不显示涨跌幅
- **新股上市不足一年**：日K线显示所有可用历史数据（可能不足3年）；MA均线在数据不足时从有数据日开始计算
- **非交易时段访问分时图**：显示最近一个交易日的分时数据，标注"非交易时段"
- **财务数据缺失**：某些股票可能缺少PE/PB等数据，对应位置显示"--"而非报错
- **关联文章超过50篇**："相关分析"标签最多展示50篇最近的文章，超出部分可通过"查看更多"或分页加载
- **AKShare数据源不可用**：显示缓存数据（如有），并提示"数据更新延迟"
- **股票代码不存在**：搜索时显示"未找到相关股票"；直接访问URL时显示404页面

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持从模块一分析文章中点击股票名称/代码，在当前页面以侧边栏/抽屉形式展示该股K线行情
- **FR-002**: 个股详情页必须展示顶部价格卡，包含股票名称、代码、当前价格、涨跌额/涨跌幅、今日成交量/成交额
- **FR-003**: K线图必须支持四种周期切换：分时（当日）、日K、周K、月K，默认展示日K
- **FR-004**: K线图必须默认展示MA（5/10/20日）均线和成交量柱状图，支持通过开关控制MACD和KDJ指标的显示/隐藏
- **FR-005**: K线图必须支持鼠标拖动平移、滚轮缩放，鼠标悬停时显示当根K线的OHLCV数据
- **FR-006**: 个股详情页底部必须提供标签页切换：基本信息、财务数据、同行对比、相关分析
- **FR-007**: "财务数据"标签必须展示PE（市盈率TTM）、PB（市净率）、最近一年营收、最近一年净利润及同比增长率
- **FR-008**: "相关分析"标签必须展示模块一知识库中涉及该股的所有历史分析文章，包含标题、摘要（≤80字）、保存日期，按日期倒序排列；点击文章跳回模块一知识库定位展开
- **FR-009**: 系统必须提供股票搜索功能，支持通过股票代码或名称进行模糊匹配搜索，输入2个字符后实时展示匹配结果
- **FR-010**: 系统必须提供自选股分组管理功能，默认3个分组（重仓股/观察股/备选股），支持新增分组（最多10个）、重命名分组、删除分组（自定义分组）
- **FR-011**: 自选股列表必须展示股票名称、代码、当前价格、今日涨跌幅、所属行业、缠论信号灯状态
- **FR-012**: 系统必须提供申万一级行业导航（31个行业），点击行业后展示该行业内股票对比表，支持按任意列排序
- **FR-013**: 个股详情页必须提供"加入自选股"按钮，支持选择分组后将股票加入对应分组；同一分组内重复添加须幂等处理（静默忽略，不报错不重复添加）
- **FR-014**: 数据展示必须标注"数据延迟15-30分钟"和"不构成投资建议"提示
- **FR-015**: 当数据不可用或加载失败时，系统必须展示友好的错误提示和重试机制

### Key Entities

- **股票（Stock）**: 代表一只A股，关键属性包括股票代码、股票名称、所属申万一级行业、所属申万二级行业、当前价格、涨跌幅、成交量、成交额
- **K线数据（KLine）**: 代表某只股票在某个时间周期的行情数据，关键属性包括时间、开盘价、最高价、最低价、收盘价、成交量；按周期分为分时/日K/周K/月K
- **财务指标（FinancialMetric）**: 代表某只股票的基本面数据，关键属性包括PE（市盈率TTM）、PB（市净率）、最近一年营收、最近一年净利润、营收同比增长率、净利润同比增长率
- **自选股分组（WatchlistGroup）**: 代表用户自定义的股票分组，关键属性包括分组名称、分组内股票列表、创建时间；与用户账号关联
- **分析文章关联（ArticleStockRelation）**: 代表模块一分析文章与股票的关联关系，关键属性包括文章ID、股票代码、股票名称；用于支撑"相关分析"标签查询
- **行业（Industry）**: 代表申万一级行业分类，关键属性包括行业名称、行业代码、行业内股票列表；共31个一级行业

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从模块一分析文章点击股票代码到侧边栏K线展示，整个过程耗时不超过1.5秒
- **SC-002**: 个股详情页K线图首次渲染耗时不超过2秒
- **SC-003**: 用户可以在3次点击内完成"发现股票 → 查看K线 → 查看财务数据"的完整流程
- **SC-004**: 搜索功能在输入2个字符后，匹配结果展示耗时不超过500毫秒
- **SC-005**: 行业对比表加载耗时不超过3秒
- **SC-006**: 日K历史数据至少覆盖最近3年的交易日
- **SC-007**: 用户在个股详情页可以完整查看4种K线周期和4个技术指标（MA/成交量/MACD/KDJ），无需离开当前页面
- **SC-008**: "相关分析"标签展示的历史文章与用户查询的股票100%匹配（无遗漏、无错误关联）

---

## Assumptions

- **数据源假设**: A股历史K线数据、实时价格、财务数据通过外部数据源获取，数据更新存在15-30分钟延迟，用户可接受
- **K线复权假设**: K线图默认使用前复权数据，不复权/后复权切换不在本期范围内
- **用户规模假设**: 初期用户同时在线量较低，单用户自选股分组最多10个、每组最多100只股票
- **模块一接口假设**: 模块一已提供文章-股票关联数据的写入和查询能力，支撑"相关分析"标签功能
- **模块三接口假设**: 模块三提供缠论信号灯查询能力，模块二在自选股列表中展示信号灯状态；模块三未接入时显示"-"占位
- **行业数据假设**: 申万行业-股票映射数据在开发前一次性初始化，每月更新一次以纳入新股
- **设备假设**: 用户主要在PC端使用，移动端适配作为后续优化项
## Clarifications

### Session 2026-04-30

- **Q1**: 默认userId的值？ → **A**: `"default"`（无登录系统，固定默认ID）
- **Q2**: 默认自选股分组何时创建？ → **A**: 首次访问自选股页面时后端自动创建（非migration预置）
- **Q3**: 模块一→模块二联动交互形式？ → **A**: 可滑出抽屉（Drawer），从右侧滑出覆盖内容，带关闭按钮和"展开完整页"按钮
- **Q4**: K线图默认展示多长时间历史数据？ → **A**: 最近6个月（用户可通过缩放查看全部3年数据）
- **Q5**: 重复添加自选股到同一分组？ → **A**: 幂等处理——静默忽略，不报错不重复添加，UI上该分组显示"已添加"不可选

## Assumptions

- **认证假设**: 当前系统无登录功能，所有用户操作使用固定默认userId `"default"`；未来接入登录系统后迁移到真实用户ID
