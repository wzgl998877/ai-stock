# Feature Specification: 个股分析界面展示优化与存档

**Feature Branch**: `005-analysis-ui-archive`
**Created**: 2025-04-25
**Status**: Draft
**Input**: User description: "个股分析完整体验升级：从启动配置页（投研工作台启动厅）→ 实时分析监控（AI投研指挥舱）→ 结构化报告呈现 → 全程增量存档 → 独立分析记录列表与详情回看"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 分析启动配置页：投研工作台启动厅 (Priority: P0) 🎯 MVP

用户从"个股分析"菜单进入后，看到一个专业的双栏配置界面：左侧配置区承载标的输入、分析模式选择和启动操作，右侧预览区展示多 Agent 协作拓扑图和历史分析快捷入口。页面顶部有系统状态栏实时显示在线状态、市场状态和数据同步情况。用户在选择"深度分析"模式时，右侧拓扑图亮起蓝色光晕表示协作模式已激活；选择"快速分析"时仅前两位分析师亮起。点击"开始分析"后按钮文字变为"正在调动分析师..."，随后进入分析执行页。

**Why this priority**: 启动页是用户的第一触点，直接决定对 AI 能力的感知。没有专业的启动体验，后续分析过程的可信度大打折扣。

**Independent Test**: 进入个股分析菜单，验证双栏布局正确渲染，顶部状态栏显示三项信息，切换分析模式时右侧拓扑图联动变化，点击启动后过渡到分析执行页。

**Acceptance Scenarios**:

1. **Given** 用户从"个股分析"菜单进入，**When** 页面加载完成，**Then** 显示双栏布局：左侧配置区（40-45%宽度）+ 右侧预览区（55-60%宽度），替换当前单栏居中布局
2. **Given** 页面加载完成，**When** 用户查看顶部，**Then** 显示微型状态栏（不超过40px高），包含：系统在线（绿色脉冲圆点+文字）、市场状态（交易中绿色/已收盘灰色）、数据已同步（灰色芯片+打勾图标），三项用竖线分隔
3. **Given** 用户查看右侧预览区，**When** 默认状态，**Then** 展示静态 AI 分析师协作拓扑图：四个节点纵向排列（技术面分析师、基本面分析师、新闻舆情哨兵、风险评估官），节点为圆角矩形卡片含图标+名称，节点间用虚线连接并标注关系词（如"交叉辩论"、"数据联动"）
4. **Given** 用户选择"深度分析"模式，**When** 模式切换，**Then** 右侧拓扑图包裹蓝色光晕边框表示协作模式已激活，拓扑图下方显示"深度分析将调动4位AI分析师，经过多空辩论与风险评估，预计3-5分钟产出完整报告"
5. **Given** 用户选择"快速分析"模式，**When** 模式切换，**Then** 拓扑图仅前两位分析师亮起，后两位置灰，下方显示"快速分析由技术面与基本面两位分析师协作，约30-60秒完成"
6. **Given** 分析模式选择器，**When** 用户查看，**Then** 显示两张可点选的模式卡片（非单选按钮）：快速分析卡片（⚡ 快速分析 · 2位分析师 · 约30-60秒）和深度分析卡片（⚡ 深度分析 · 4位分析师+辩论+风评 · 约3-5分钟），选中卡片有蓝色高亮边框+微蓝背景
7. **Given** 用户输入有效股票并点击"开始分析"，**When** 按钮点击后，**Then** 按钮文字变为"正在调动分析师..."，300ms后进入分析执行页面
8. **Given** 右侧预览区，**When** 该股票存在历史分析记录，**Then** 在拓扑图下方展示最近3条历史分析快捷入口，点击可直接载入该报告
9. **Given** 左侧配置区底部，**When** 页面渲染，**Then** 固定显示合规提示："本工具仅供投研参考，不构成任何投资建议"，小号灰色文字

### User Story 2 - 分析过程实时可视化 (Priority: P1)

无论快速还是深度分析，执行界面采用统一的布局和交互体验：左侧面板展示 Agent 运行状态，右侧内容区随阶段自动切换展示对应的分析内容。

- **深度分析**：左侧面板显示 4 个阶段（分析师→辩论→决策→风险）共 12 个 Agent 的实时运行状态，右侧内容区按阶段自动切换。阶段之间的切换由后端真实执行进度驱动，前端不自主提前推进。已完成阶段的内容可折叠为一行摘要，点击回看展开但不影响当前阶段的主显示区。
- **快速分析**：左侧面板显示 1 个阶段（分析师）共 2 个 Agent（技术面+基本面）的运行状态，界面布局、交互方式（状态图标、动画、折叠等）与深度分析完全一致。右侧内容区展示分析师卡片。快速分析完成后同样展示投资决策卡片。

两种模式都支持"查看详细推理"展开全量文本、停止分析确认弹窗、错误友好提示。

**Why this priority**: 实时可视化是分析体验的核心，阶段联动和全量展示直接关系到用户能否有效获取分析信息。快速和深度分析共享统一体验，降低用户学习成本。

**Independent Test**: 分别发起快速分析和深度分析，验证两种模式使用相同的页面布局和交互方式（左侧状态面板+右侧内容区），快速分析仅展示分析师阶段和决策，深度分析展示全部4个阶段。

**Acceptance Scenarios**:

1. **Given** 深度分析流程启动，**When** 页面进入执行态，**Then** 左侧面板显示 4 个阶段（分析师→辩论→决策→风险）共 12 个 Agent，所有状态为"就绪"（灰色时钟图标）
2. **Given** 快速分析流程启动，**When** 页面进入执行态，**Then** 左侧面板显示 1 个阶段（分析师）共 2 个 Agent（技术面分析师+基本面分析师），界面布局与深度分析一致（左侧状态面板+右侧内容区）
3. **Given** 分析流程运行中，**When** 某个 Agent 开始工作，**Then** 该 Agent 状态变为"分析中"（蓝色旋转图标+脉冲圆点），头像加呼吸光晕动画（快速和深度行为一致）
4. **Given** 某个 Agent 完成，**When** 状态更新为"已完成"，**Then** 显示绿色对勾图标+完成时间戳，视觉权重降低（opacity 0.65）
5. **Given** 深度分析运行中，**When** 阶段从"分析师"切换到"辩论"，**Then** 右侧展示区自动切换为辩论区内容（看多/看空研究员+研究主管），顶部步骤条平滑过渡（0.3s动画）
6. **Given** 快速分析运行中，**When** 技术面分析师完成，**Then** 右侧该分析师卡片展示完成状态，基本面的分析师继续"分析中"
7. **Given** 深度分析中分析师阶段已完成且当前为辩论阶段，**When** 查看左侧面板，**Then** 分析师阶段内容折叠为一行"分析师阶段已完成 ✓ · 点击回看"，点击可展开完整内容但不影响辩论阶段的主显示
8. **Given** 用户点击某分析师卡片的"查看详细推理"，**When** 内容展开，**Then** 渲染该分析师的完整全量输出文本，无任何截断，展开容器有独立滚动条（快速和深度行为一致）
9. **Given** 分析过程中网络中断，**When** SSE 流异常断开，**Then** 界面展示友好的错误提示，已收到的部分结果不丢失

### User Story 3 - 分析结果结构化呈现 (Priority: P2)

分析完成后（或从记录回看时），用户看到一份结构化的投研报告。无论快速还是深度分析，结果页的呈现风格一致：

- **深度分析完成**：按顺序展示分析概要 → 投资决策 → 分析师报告（4位分析师独立卡片）→ 投资辩论（分栏对比）→ 风险评估（5个角色独立卡片）
- **快速分析完成**：按顺序展示分析概要 → 投资决策 → 分析师报告（2位分析师独立卡片）。不展示辩论和风险评估区域，但其余区域的卡片样式、交互方式（首句加粗、折叠展开、数字高亮）与深度分析完全一致

每位分析师/研究员渲染为独立卡片，内含角色标识行、结论摘要行（加粗）、详情入口（默认折叠）和展开详情区。投资辩论区按轮次左右分栏对比（绿/红主题），研究主管总结置顶。文本中关键数字自动高亮，风险评分配合色阶条展示。底部合规提示恒常置底。

**Why this priority**: 结构化呈现是"更好看更专业"的核心交付物，让用户快速扫描结论再按需展开细节。快速和深度分析共享统一的呈现风格，保持体验一致性。

**Independent Test**: 分别完成快速分析和深度分析，验证两种模式的结果展示使用相同的卡片样式和交互方式（首句加粗+折叠+数字高亮），快速分析仅展示概要+决策+2位分析师报告，深度分析展示完整5个区域。

**Acceptance Scenarios**:

1. **Given** 深度分析完成，**When** 用户查看右侧面板，**Then** 按顺序展示：分析概要 → 投资决策 → 分析师报告（4位） → 投资辩论 → 风险评估
2. **Given** 快速分析完成，**When** 用户查看右侧面板，**Then** 按顺序展示：分析概要 → 投资决策 → 分析师报告（2位：技术面+基本面），不展示辩论和风险评估区域
3. **Given** 某位分析师的卡片（快速或深度），**When** 查看卡片内容，**Then** 自上而下展示：角色标识行（头像图标+角色名称+状态标签+时间戳）、结论摘要行（首句加粗）、详情入口"查看详细推理"（默认折叠）、展开详情区（完整推理，独立滚动），卡片样式在两种模式下完全一致
4. **Given** 投资辩论区（仅深度分析），**When** 内容存在，**Then** 研究主管总结置顶于辩论区最上方居中显示，看多观点（绿色边框）与看空观点（红色边框）按轮次左右分栏对比
5. **Given** 风险评估区（仅深度分析），**When** 内容存在，**Then** 5 个角色（交易决策官、激进派、保守派、中立派、风险裁决官）各自独立卡片展示；未到达该阶段时显示暗色剪影+"待前置阶段完成后触发"
6. **Given** 文本中包含价格或百分比数字，**When** 内容渲染，**Then** 这些数字以主题色加粗高亮显示（快速和深度行为一致）
7. **Given** 风险评分存在，**When** 用户查看风险评分，**Then** 展示色阶条 + 数值 + 风险等级文字，色阶按 0-30 绿 / 31-60 黄 / 61-80 橙 / 81-100 红
8. **Given** 某个风险角色在辩论中没有输出，**When** 渲染该角色卡片，**Then** 保留卡片框架并显示"暂无输出"
9. **Given** 分析完成后的页面任意滚动位置，**When** 查看页面底部，**Then** 合规提示始终可见（"本工具仅供投研参考，不构成任何投资建议"），不随内容滚动消失（快速和深度行为一致）

### User Story 4 - 分析增量存档 (Priority: P3)

分析过程中，系统全程自动保存，快速和深度分析均适用。用户点击"开始分析"时，后端立即创建一条状态为"进行中"的分析记录。每完成一个阶段，后端立即将该阶段所有 Agent 的完整输出和状态写入这条记录。用户中途停止分析或页面意外断开时，已完成的阶段数据不丢失。分析记录的状态枚举包含"进行中"、"已完成"和"已停止"。

**Why this priority**: 增量存档是历史回顾和断点恢复的数据基础。没有增量保存，用户退出后无法看到部分完成的分析进度。快速分析同样需要存档，确保所有分析记录统一管理。

**Independent Test**: 分别发起快速分析和深度分析，在各阶段完成后检查后端记录，验证增量数据写入正确。快速分析仅含分析师阶段数据，深度分析含全部阶段数据。

**Acceptance Scenarios**:

1. **Given** 用户点击"开始分析"（快速或深度），**When** 后端接收请求，**Then** 立即创建一条分析记录，状态为"进行中"，记录包含标的名称/代码、分析模式、创建时间
2. **Given** 分析流程执行中（快速或深度），**When** 分析师阶段完成，**Then** 后端立即将该阶段所有 Agent 的完整输出文本和时间戳写入该条记录
3. **Given** 深度分析流程执行中，**When** 后续每个阶段完成（辩论、决策、风险），**Then** 后端立即将该阶段完整数据追加写入记录
4. **Given** 快速分析全流程完成，**When** 分析师阶段+决策完毕，**Then** 记录状态更新为"已完成"，包含分析师报告和投资决策数据
5. **Given** 深度分析全流程完成，**When** 所有阶段执行完毕，**Then** 记录状态更新为"已完成"，包含完整结构化数据（所有 Agent 报告、多轮辩论、投资决策、标题、摘要、行业标签）
6. **Given** 用户点击"停止分析"并确认（快速或深度），**When** 后端停止任务，**Then** 记录状态更新为"已停止"，已完成的阶段数据保留不丢失
7. **Given** 分析过程中页面意外断开（快速或深度），**When** 用户重新进入，**Then** 已保存的阶段数据不丢失，可通过分析记录列表找到该条记录

### User Story 5 - 分析记录列表页与详情回看 (Priority: P4)

用户通过左侧导航栏的"分析记录"菜单进入独立的记录列表页。列表按最后更新时间倒序排列，每条记录以卡片形式展示：标的名称/代码、分析模式、进度条（已完成阶段数/总阶段数）、状态标识（进行中/已完成/已停止）、最后更新时间和"查看详情"操作入口。点击"查看详情"跳转至分析执行页，加载该记录的完整存档数据并渲染结构化报告。若记录状态为"进行中"，页面接续接收后端实时流式输出。

**Why this priority**: 列表页是分析记录的统一入口，配合详情回看形成完整的"分析→存档→回看"闭环。

**Independent Test**: 完成多次分析后，通过左侧菜单进入分析记录列表，验证列表排序、状态标识和进度条正确，点击"查看详情"跳转并完整还原结构化报告。

**Acceptance Scenarios**:

1. **Given** 用户点击左侧导航栏"分析记录"菜单，**When** 进入列表页，**Then** 显示所有分析记录，按最后更新时间倒序排列
2. **Given** 列表中存在记录，**When** 用户查看某条卡片，**Then** 卡片展示：标的名称/代码、分析模式标签（快速/深度）、微型进度条（已完成阶段数/总阶段数）、状态标识（🟢已完成/🟡进行中/⚪已停止）、最后更新时间、"查看详情"按钮
3. **Given** 用户点击某条记录的"查看详情"，**When** 跳转到分析执行页，**Then** 页面以"查看模式"加载该记录的完整存档数据，左侧步骤条标记已完成阶段，右侧渲染完整结构化报告（概要→决策→报告→辩论→风险）
4. **Given** 记录状态为"进行中"，**When** 用户进入详情页，**Then** 前端建立连接接续接收后端实时流式输出，新输出追加渲染在页面上
5. **Given** 记录状态为"已完成"或"已停止"，**When** 用户进入详情页，**Then** "停止分析"按钮置灰或隐藏
6. **Given** 没有任何分析记录，**When** 用户进入列表页，**Then** 显示空状态："暂无分析记录" + "开始你的第一次个股深度分析" + "去分析"引导按钮
7. **Given** 分析执行页底部的"历史分析"区域，**When** 分析完成，**Then** 显示最近 3 条记录（快捷入口），点击可跳转至详情页

### Edge Cases

- 快速模式和深度模式在执行界面使用统一布局和交互，仅 Agent 数量和阶段数不同
- 快速模式仅 1 个阶段（分析师，2个Agent）+ 决策，进度条总阶段数为 1；深度模式 4 个阶段（12个Agent）+ 决策
- 分析过程中网络中断，已收到的部分结果不丢失，界面展示错误提示而非技术报错原文
- 失败的分析维度以灰色卡片展示，内容显示"该维度分析暂未完成"
- "查看详细推理"展开后收起，阅读位置重置到顶部
- 文本高亮不应误匹配非财务数字（如"3月"、"第4轮"中的数字）
- 合规提示在任何滚动位置都保持可见，不干扰主内容阅读
- 详情页中的分析结果为历史快照，不随时间更新（不显示实时价格）
- "重新分析"按钮点击后弹出二次确认，确认后保留当前结果到记录
- 存档数据量过大时（辩论轮次异常多），详情页仍需在 3 秒内完成渲染
- 系统状态栏的市场状态需根据实际交易时间动态切换
- 快速分析从记录回看时，仅渲染分析师和决策区域，辩论和风险区域不显示

## Requirements *(mandatory)*

### Functional Requirements

**启动配置页**

- **FR-001**: 个股分析入口页 MUST 采用双栏布局（左侧配置区 40-45% + 右侧预览区 55-60%），替换当前单栏居中布局
- **FR-002**: 页面顶部 MUST 显示微型状态栏（不超过40px），包含系统在线（绿色脉冲）、市场状态（交易中/已收盘）、数据已同步（灰色芯片+打勾），三项用竖线分隔
- **FR-003**: 右侧预览区 MUST 展示多 Agent 协作拓扑图（4个节点纵向排列+虚线连接+关系词标注），节点为圆角矩形卡片含图标和名称
- **FR-004**: 选择"深度分析"模式时，拓扑图 MUST 包裹蓝色光晕边框；选择"快速分析"时，仅前两位分析师亮起，后两位置灰
- **FR-005**: 分析模式选择 MUST 使用两张可点选的模式卡片（非单选按钮），选中卡片有蓝色高亮边框+微蓝背景
- **FR-006**: 拓扑图下方 MUST 根据所选模式显示不同说明文字（深度/快速分析的时间与参与者说明）
- **FR-007**: "开始分析"按钮点击后 MUST 显示过渡动效（文字变为"正在调动分析师..."），300ms后进入分析执行页
- **FR-008**: 当该股票存在历史分析时，右侧预览区 MUST 在拓扑图下方展示最近3条历史分析快捷入口

**分析过程可视化**

- **FR-009**: 左侧面板 MUST 展示各 Agent 的运行状态，深度分析显示 4 阶段 12 个 Agent，快速分析显示 1 阶段 2 个 Agent（技术面+基本面），两种模式使用统一的状态图标：就绪=灰色时钟、分析中=蓝色旋转动画、已完成=绿色对勾+时间戳、失败=红色叉号+时间戳
- **FR-010**: 同一阶段内的 Agent 节点间 MUST 显示连接线，颜色按状态动态变化（完成=绿、进行中=蓝、未开始=灰）
- **FR-011**: 顶部步骤条 MUST 与左侧面板联动，深度分析 4 步骤、快速分析 1 步骤，阶段切换时平滑过渡（0.3s动画），当前阶段呼吸光效，已完成打勾，未开始置灰
- **FR-012**: 右侧展示区 MUST 随当前阶段自动切换内容，深度分析按阶段（分析师→辩论→决策→风险）切换，快速分析展示分析师内容+决策，由后端真实执行进度驱动
- **FR-013**: 深度分析中已完成阶段 MUST 自动折叠为一行"XX阶段已完成 ✓ · 点击回看"，点击可展开但不影响当前阶段主显示；快速分析仅 1 个阶段无需折叠
- **FR-014**: "查看详细推理"展开后 MUST 渲染该 Agent 的全量输出文本，无截断，展开容器有独立滚动条（快速和深度分析行为一致）
- **FR-015**: "停止分析"按钮点击后 MUST 弹出确认弹窗，确认后停止后端任务并保留已完成内容（快速和深度分析行为一致）

**结构化报告呈现**

- **FR-016**: 每位分析师/研究员 MUST 渲染为独立卡片，内含：角色标识行（头像图标+角色名称+状态标签+时间戳）、结论摘要行（首句加粗）、详情入口（默认折叠）、展开详情区（全量推理+独立滚动）
- **FR-017**: 投资辩论区（仅深度分析）MUST 按轮次配对左右分栏展示看多（绿色边框）与看空（红色边框），研究主管总结置顶于辩论区上方居中
- **FR-018**: 风险辩论区（仅深度分析）MUST 同样分栏展示激进派与保守派，中立派居中通栏，风险裁决官总结置顶
- **FR-019**: 文本中关键财务数字（价格、百分比）MUST 自动识别并高亮（快速和深度分析行为一致）
- **FR-020**: 风险评分 MUST 配合色阶条+数值+风险等级文字展示：0-30绿/31-60黄/61-80橙/81-100红
- **FR-021**: 风险阶段5个角色（仅深度分析）MUST 各自独立卡片展示，无输出时显示"暂无输出"
- **FR-022**: 底部合规提示 MUST 恒常置底，文案包含"不构成任何投资建议"字样

**增量存档**

- **FR-023**: 用户点击"开始分析"时（快速或深度），后端 MUST 立即创建分析记录，状态为"进行中"
- **FR-024**: 每个阶段完成时（快速和深度均适用），后端 MUST 立即将该阶段所有 Agent 完整输出文本和状态写入记录
- **FR-025**: 分析记录状态 MUST 支持"进行中"/"已完成"/"已停止"三种状态
- **FR-026**: 分析全流程完成时，记录 MUST 包含对应模式的完整结构化数据（快速模式：分析师报告+决策；深度模式：所有Agent报告+辩论数据+投资决策+标题+摘要+行业标签）
- **FR-027**: 用户停止分析时，MUST 保留已完成阶段数据，记录状态更新为"已停止"
- **FR-028**: 后端 MUST 提供按 ID 查询单条分析记录完整数据的接口，返回数据足以还原结构化报告展示

**分析记录列表与详情**

- **FR-029**: 左侧导航栏 MUST 新增"分析记录"一级菜单入口
- **FR-030**: 分析记录列表页 MUST 按最后更新时间倒序排列所有记录
- **FR-031**: 每条记录卡片 MUST 展示：标的名称/代码、分析模式、微型进度条（已完成阶段数/总阶段数）、状态标识（进行中/已完成/已停止）、最后更新时间、"查看详情"按钮
- **FR-032**: 点击"查看详情"MUST 跳转到分析执行页，以查看模式加载完整存档数据并渲染结构化报告
- **FR-033**: 记录状态为"进行中"时，详情页 MUST 接续接收后端实时流式输出
- **FR-034**: 记录状态为"已完成"或"已停止"时，详情页"停止分析"按钮 MUST 置灰或隐藏
- **FR-035**: 无记录时列表页 MUST 显示空状态引导："暂无分析记录" + "去分析"按钮
- **FR-036**: 分析执行页底部"历史分析"区域 MUST 显示最近3条记录作为快捷入口
- **FR-037**: "重新分析"按钮点击后 MUST 弹出二次确认弹窗，确认后保留当前结果到记录并重置界面

### Key Entities

- **分析记录（Analysis Record）**: 一次完整的个股分析存档，包含记录ID、标的名称/代码、分析模式（快速/深度）、分析状态（进行中/已完成/已停止）、创建时间、最后更新时间、各阶段完整数据（Agent报告+辩论+决策+风险评估）
- **Agent 报告（Agent Report）**: 某个 Agent 的输出摘要文本，与 Agent 标识关联，含完成时间戳
- **辩论事件（Debate Event）**: 辩论参与者在某轮次的发言，包含发言人标识、轮次号、发言内容
- **投资决策（Investment Decision）**: 交易决策官的最终输出，包含操作方向、目标价、置信度、风险评分、决策依据
- **阶段进度（Phase Progress）**: 分析记录中各阶段的完成状态，用于计算进度条（已完成阶段数/总阶段数）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户进入个股分析页后，3 秒内感知到 AI 多 Agent 能力（通过右侧拓扑图和模式说明文字）
- **SC-002**: 从点击"开始分析"到看到第一个 Agent 开始工作，过渡不超过 2 秒
- **SC-003**: Agent 的状态变化在 0.5 秒内反映到界面上（快速模式 2 个 Agent、深度模式 12 个 Agent）
- **SC-004**: 右侧内容区随阶段切换无延迟，已完成阶段可一键折叠/展开
- **SC-005**: 用户能在 5 秒内从结构化报告中定位到核心投资决策
- **SC-006**: "查看详细推理"展开后显示全量文本，不出现截断
- **SC-007**: 多空辩论对比布局让用户在 10 秒内理解正反双方核心观点
- **SC-008**: 分析过程中断后重新进入，已完成的阶段数据完整可查
- **SC-009**: 从分析记录列表点击"查看详情"到页面渲染完成不超过 3 秒
- **SC-010**: 合规提示在任何滚动位置都保持可见，不干扰主内容阅读

## Assumptions

- 后端 SSE 流已支持 agent_status、agent_report、debate、decision 等事件类型的推送
- 数据库已有 `analysis_data` JSON 字段可用于存储结构化数据（需确认并启用写入）
- 市场状态可根据交易时间规则计算（A股交易日 9:30-15:00），无需外部数据源
- 系统在线状态默认为在线，无需健康检查接口（初期版本）
- 数据同步状态默认为已同步（初期版本）
- 分析维度芯片初期版本为展示用途，暂不实现按维度过滤后端 Agent 的功能
- 分析详情页复用现有分析执行页面的组件和布局，以"查看模式"展示
- 用户设备为桌面浏览器（1920x1080 及以上），移动端适配不在本期范围
- 快速模式和深度模式共享统一的执行页面和结果页面，差异仅在于：快速模式 1 阶段（2 个 Agent），深度模式 4 阶段（12 个 Agent）
- 快速分析完成后也会生成投资决策，但无辩论和风险评估数据
