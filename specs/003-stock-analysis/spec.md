# Feature Specification: 个股多Agent深度分析

**Feature Branch**: `003-stock-analysis`
**Created**: 2026-04-22
**Status**: Draft
**Input**: User description: "帮我加个模块功能，功能是个股分析，将 TradingAgents-CN 分析功能加到我现在的项目中"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 个股深度分析 (Priority: P1)

用户在个股详情页或分析页输入一只A股股票代码/名称，系统通过多个AI Agent协作（技术面、基本面、新闻、情绪四位分析师 → 看多看空辩论 → 风险辩论），实时流式展示分析过程与结论，最终生成结构化的深度分析报告（含买卖建议、目标价、置信度、风险评分）。报告自动保存到知识库，与该股票关联。

**Why this priority**: 这是本功能的核心价值——将TradingAgents-CN的多Agent协作分析能力带给用户，比单一LLM分析更全面、更有决策参考价值。没有这个能力，本功能不存在。

**Independent Test**: 输入一只A股代码，能走通"发起分析 → 实时看到各Agent思考过程 → 得到结构化报告 → 报告保存到知识库"完整链路。

**Acceptance Scenarios**:

1. **Given** 用户在个股分析页面，**When** 输入"宁德时代"或"300750"并点击"深度分析"，**Then** 系统发起多Agent分析流程，页面显示分析进行中状态
2. **Given** 分析流程已启动，**When** 各Agent开始工作，**Then** 页面实时流式展示当前哪个Agent在工作（如"技术面分析中..."/"基本面分析中..."/"看多辩论中..."），已完成的Agent结论可随时查看
3. **Given** 所有Agent分析完成，**When** 最终决策生成，**Then** 页面展示完整的结构化分析报告，包含：技术面摘要、基本面摘要、新闻摘要、情绪摘要、看多论据、看空论据、投资计划、风险辩论摘要、最终决策（买入/持有/卖出 + 目标价 + 置信度 + 风险评分）
4. **Given** 分析报告生成完成，**When** 用户确认保存，**Then** 报告以文章形式存入知识库，自动关联该股票代码，可在知识库股票视图中查看
5. **Given** 分析报告含"不构成投资建议"免责声明，**When** 用户查看报告任何部分，**Then** 均可看到明显的免责提示

---

### User Story 2 - 分析过程可视化 (Priority: P2)

用户发起个股分析后，可以看到多Agent工作的进度和中间结果，而不是只等最终结果。每个Agent完成时，其分析摘要立即可见，用户可以中途查看已完成的部分。

**Why this priority**: 多Agent分析耗时较长（2-5分钟），如果只显示loading会严重影响体验。实时展示各Agent的进展和中间结果，让用户感知到"系统在认真工作"，同时中间结果本身也有参考价值。

**Independent Test**: 发起分析后，能在30秒内看到第一个Agent（技术面分析师）的输出，后续Agent依次输出，无需等待全部分析完成。

**Acceptance Scenarios**:

1. **Given** 用户发起分析，**When** 技术面分析师开始工作，**Then** 页面在5秒内显示"技术面分析中..."状态指示
2. **Given** 技术面分析师完成分析，**When** 其结论写入状态，**Then** 页面立即展示技术面分析摘要卡片，同时下一个Agent开始工作
3. **Given** 投资辩论阶段开始，**When** Bull和Bear交替发言，**Then** 页面实时展示看多/看空论据的对话式输出
4. **Given** 用户中途关闭页面，**When** 重新打开，**Then** 分析任务仍在后台运行，完成后可在知识库查看结果

---

### User Story 3 - 分析历史与对比 (Priority: P3)

用户可以查看某只股票的历史深度分析记录，对比不同时间点的分析结论和市场变化，辅助复盘。

**Why this priority**: 复盘是散户提升投研能力的核心环节，历史分析对比能帮助用户评估分析的准确性和自身决策质量。但这是增值功能，P1完成后再实现。

**Independent Test**: 对同一只股票进行两次分析后，能在个股页面查看两次分析的结果对比。

**Acceptance Scenarios**:

1. **Given** 用户查看某只股票的详情页，**When** 切换到"深度分析"标签，**Then** 显示该股票所有历史深度分析记录，按时间倒序排列
2. **Given** 存在多条历史分析，**When** 用户选择两条进行对比，**Then** 页面并排展示两次分析的最终决策、目标价、置信度、风险评分
3. **Given** 历史分析中的目标价可验证，**When** 当前股价已远离目标价，**Then** 页面标注实际涨跌幅度，辅助用户复盘

---

### User Story 4 - 快速分析模式 (Priority: P4)

用户不需要完整的4Agent+辩论流程，只需快速了解某只股票的基本情况。系统仅运行技术面+基本面两位分析师，1分钟内给出简要分析。

**Why this priority**: 完整分析耗时较长，日常浏览多只股票时需要快速筛选。但这是优化体验的功能，核心分析能力（P1）优先。

**Independent Test**: 选择"快速分析"模式后，60秒内得到包含技术面+基本面摘要的简要报告。

**Acceptance Scenarios**:

1. **Given** 用户在分析输入区，**When** 选择"快速分析"模式，**Then** 系统仅运行技术面和基本面两位分析师
2. **Given** 快速分析模式启动，**When** 两位分析师完成，**Then** 1分钟内生成简要分析报告（无辩论环节），包含技术面摘要、基本面摘要、简要建议

---

### Edge Cases

- 用户输入无效的股票代码或名称时，系统给出明确的错误提示"未找到该股票，请检查代码或名称"
- 股票停牌时，系统仍可基于历史数据进行分析，但标注"该股票当前停牌，分析基于最近交易日数据"
- 分析过程中LLM调用失败时，已完成的Agent结果保留，失败的Agent标注"数据获取失败"，最终报告降级生成
- 某只股票的金融数据源全部不可用时（如退市股票），系统提示"该股票数据不可用，无法进行分析"
- 用户对同一只股票在5分钟内重复发起分析时，提示"该股票5分钟内已有分析，是否查看最近的分析结果？"
- 分析任务超过10分钟未完成时，自动终止并保留已完成的部分结果
- 用户在分析进行中发起新的分析请求时，提示"当前有分析进行中，请等待完成或取消后再试"

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持用户输入A股股票代码或名称，发起多Agent深度分析
- **FR-002**: 系统必须通过4位专业化分析师（技术面、基本面、新闻、情绪）独立分析股票，每位分析师可调用金融数据工具获取实时数据
- **FR-003**: 系统必须在4位分析师完成后，启动看多（Bull）与看空（Bear）辩论环节，多轮交替论证
- **FR-004**: 系统必须在辩论完成后，由Research Manager裁决辩论并生成投资计划
- **FR-005**: 系统必须在投资计划基础上，由Trader生成交易建议（买入/持有/卖出 + 目标价）
- **FR-006**: 系统必须在交易建议基础上，启动三方风险辩论（激进/保守/中立），最终由Risk Judge生成风险裁决
- **FR-007**: 系统必须将整个分析过程以流式方式实时输出，用户无需等待全部分析完成即可看到中间结果
- **FR-008**: 系统必须从最终决策中提取结构化信号：操作方向（买入/持有/卖出）、目标价、置信度（0-100%）、风险评分（0-100%）
- **FR-009**: 系统必须将分析报告保存到知识库，自动关联股票代码和行业标签
- **FR-010**: 系统必须在所有分析结果和决策建议中包含"不构成投资建议"免责声明
- **FR-011**: 系统必须支持分析师调用金融数据工具获取股票行情、基本面、新闻、情绪数据
- **FR-012**: 系统必须在分析师工具调用失败时自动降级（尝试备用数据源），而非直接报错
- **FR-013**: 系统必须防止分析师工具调用死循环（每位分析师最多调用工具3次）
- **FR-014**: 系统必须支持用户查看某只股票的历史深度分析记录
- **FR-015**: 系统必须支持快速分析模式（仅技术面+基本面，无辩论环节，1分钟内完成）
- **FR-016**: 系统必须支持完整分析模式（4分析师+辩论+风险辩论，全流程输出）
- **FR-017**: 分析任务必须在后台运行，用户可切换页面而不中断分析
- **FR-018**: 系统必须对分析报告自动生成标题（≤15字）和摘要（≤80字）

### Key Entities

- **StockAnalysisTask（分析任务）**: 代表一次个股深度分析，包含股票代码/名称、分析模式（快速/完整）、各阶段状态（分析师/辩论/风险）、创建时间、完成时间
- **AgentReport（Agent分析报告）**: 单个Agent的分析输出，包含Agent类型（技术面/基本面/新闻/情绪）、分析内容、使用的数据源、生成时间
- **DebateRecord（辩论记录）**: 看多/看空或风险辩论的过程记录，包含辩论轮次、各方论据、辩论结论
- **AnalysisDecision（分析决策）**: 最终结构化决策，包含操作方向、目标价、置信度、风险评分、决策理由
- **StockAnalysisArticle（分析文章）**: 保存到知识库的完整分析报告，包含标题、摘要、各Agent报告、辩论记录、最终决策、关联股票、关联行业、免责声明

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户输入股票代码后，5秒内看到第一个Agent开始工作的状态指示
- **SC-002**: 完整分析模式在5分钟内完成全流程，快速分析模式在1分钟内完成
- **SC-003**: 90%的A股股票代码能被正确识别和分析
- **SC-004**: 分析报告的结构化决策提取成功率不低于95%（操作方向、置信度、风险评分必须提取成功）
- **SC-005**: 单次数据源失败时，系统在3秒内自动切换到备用数据源完成数据获取
- **SC-006**: 用户能在知识库股票视图中找到该股票的所有历史深度分析文章
- **SC-007**: 分析进行中用户切换页面后，任务不中断，完成后可在知识库查看结果

## Assumptions

- 目标用户与现有产品一致：A股散户，非专业投资者
- A股数据源复用现有项目的数据接入，同时引入多源故障转移机制确保数据获取可靠性
- 大模型调用复用现有项目的统一AI调用层，保持一致的调用和流式输出方式
- 工作流编排复用现有项目的工作流引擎，参考TradingAgents-CN的Graph编排模式构建多Agent工作流
- 向量记忆与反思功能暂不实现，第一版聚焦核心分析能力，后续版本可扩展
- 辩论轮次支持配置化（默认投资辩论2轮，风险辩论2轮），不硬编码
- 深度思考LLM（deep_thinking_llm）用于Research Manager和Risk Judge，快速思考LLM用于分析师和辩论者，与TradingAgents-CN策略一致
- 前端复用现有的流式输出接收机制，不引入新的通信方式
- 分析结果与现有知识库体系打通，复用ArticleArticleStock关联机制
- 个股深度分析作为模块一的增强功能，与现有事件分析共存，非替代关系
- 港股/美股分析暂不支持，第一版仅支持A股
