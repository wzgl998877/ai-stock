# Contract: 微信消息协议（对外）

**Phase 1 输出** · 2026-08-21 · 用户可感知的指令集与系统回复契约。本契约的甲方是微信侧用户，乙方是系统；协议承载于 iLink 文本消息（单向上限 ~4000 字符）。

## 1. 指令语法

### 1.1 精确指令（P1，规则层直达，不依赖 AI 服务）

| 指令 | 语义 | 等价自然语言（AI 层可识别） |
|---|---|---|
| `跑缠论` | 全部自选股缠论计算（30m + 日线双跑，2026-08-26 起默认双周期） | "帮我把自选股的缠论都跑一遍" |
| `缠论 002940` | 单股缠论计算（双周期） | "002940 现在缠论什么情况" |
| `缠论 日线 [代码]` | 只跑日线（补 15:40 定时扫描漏算的日线） | "把 002940 的日线缠论跑一下" |
| `缠论 30分钟 [代码]` | 只跑 30m | "跑下 30 分钟缠论" |
| `缠论状态` | 当前缠论任务进度 | "缠论跑得怎么样了" |
| `执行记录` | 最近 10 条指令及状态 | "最近都执行了什么" |
| `帮助` | 指令列表 | "?" |

### 1.2 自然语言（P2 起，LLM 意图层）

- 任意口语表述，LLM 解析为 `{tool_name, params}`；解析失败回帮助文案
- 多轮指代：上下文窗口 5 轮 / 30 分钟（"它"→ 上一轮提到的股票）

## 2. 系统回复类型（乙方承诺）

| 类型 | 触发 | 时限（spec SC） | 形态 |
|---|---|---|---|
| `ACK` | 慢指令受理 | 收到后 60s 内（目标：轮询周期内即时） | `收到，开始{任务}（{范围}，预计{时长}）` |
| `DIRECT_RESULT` | 快指令 | 30s 内 | 结果正文 |
| `PROGRESS` | 慢指令执行中重复询问 | 30s 内 | `正在执行{任务}，进度 {n}/{m}` |
| `RESULT` | 慢指令终态 | 终态后 60s 内 | 摘要 ≤500 字；信号类含「不构成投资建议」尾注 |
| `FAIL` | 慢指令失败 | 终态后 60s 内 | `失败：{对象}——{原因}`（禁止静默） |
| `CLARIFY` | 参数非法/歧义 | 即时 | 指出问题 + 引导修正（如"002940 不在自选池，要加入吗？"） |
| `HELP` | 未识别 / "帮助" | 即时 | 指令列表 + 示例 |
| `DENY` | 未授权发送者 | 即时 | `未授权的助手使用者`，不执行任何任务 |
| `BUSY` | 同类任务在跑 | 即时 | `已有{任务}在执行，进度 {n}/{m}`（不重复启动） |
| `CONFIRM_ASK` / `CONFIRM_DONE` | 写操作（P3） | 即时 / 确认后 | 复述操作→"回复 y 确认"；确认后回执 |

## 3. 时序承诺（两段式应答）

```
用户 ──"跑缠论"──→ 系统
用户 ←──ACK（≤60s）──  系统（后台执行）
用户 ←──RESULT/FAIL（终态后≤60s）── 系统
```

- ACK 之后、终态之前的任意询问（"缠论状态"）→ `PROGRESS`
- 推送不保证送达（iLink 已知限制）：所有终态以 `执行记录` 查询为准（100% 可查）

## 4. 消息边界

- 单条回复 ≤3800 字符（超限由结果渲染层裁剪为摘要 + "详情见网页端"）
- 仅支持文本；图片/语音消息忽略（不留指令记录）
- bot 自身消息回显（`message_type != 1`）不进入协议处理

## 5. 兼容性

- P1 上线即取代现有占位 ACK 文案「在呢，有什么问题随时找我 👌」：可识别指令按本协议回复；未识别消息回 `HELP`（保持"发消息有回应"的既有体验）
- 现有缠论信号定时推送（`chanlun_signal_push`）与本协议并行共存，互不干扰
